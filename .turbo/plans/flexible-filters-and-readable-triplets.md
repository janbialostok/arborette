# Plan: Flexible Intervention Filters + Readable Triplets (categorical/boolean segmentation, richer SSE payload, deeper search)

## Context

The live Spaceship Titanic run surfaced three gaps in the hypothesis loop:

1. **Triplets are opaque in the UI.** The `triplet` SSE event carries only node IDs + numbers (`{state_id, intervention_id, outcome_id, baseline, value, effect_size}`), so the web card can render a hash and a delta but not *which segment* the triplet measured or *which direction* is "improvement". `EffectReadout.tsx` even colors every positive delta green regardless of whether the objective is a maximize or minimize — its own comment flags that the direction "isn't carried by the live stream."

2. **Intervention filters can't target boolean/categorical columns.** `domain.Constraint` is `{Field, Op ∈ {lt,lte,gt,gte}, Value float64}` — a numeric threshold only — and the sandbox `compileFilters` rejects any filter on a non-numeric column outright. So the model's natural segments (`CryoSleep = true`, `HomePlanet = 'Europa'`) become non-terminal branch failures, and the tree can only split on numeric columns. This is the *filter* analog of the gap the objective value expression just closed (commit `b9f40b9`/`152c66c`): the objective already coerces booleans/categoricals (`avg(Transported = True)` compiles a `comparison` to a 0/1 `CASE`), but `compileFilters` got none of that treatment.

3. **The search is shallow.** `defaultDepth = 2` caps the tree at two levels; deeper causal refinement isn't explored.

This plan (a) enriches the `triplet` SSE payload with the segment's effective filters and the objective label + direction and renders them on the card; (b) extends the intervention filter model to equality (`=`), inequality (`!=`), and set membership (`IN`/`NOT IN`) on boolean and categorical/string columns (numeric threshold ops unchanged), mirroring the objective's typed-value + sandbox-coercion pattern; and (c) raises `defaultDepth` to 4.

**Decisions resolved in turboplan:**
- **Filter operators (intervention filters only):** the richer set — add `eq`, `neq`, `in`, `not_in` alongside the existing `lt`/`lte`/`gt`/`gte`. Booleans/categoricals get equality + membership; numeric columns keep threshold ops. **The matrix's hard constraints stay numeric-only.** Intervention filters (candidate segmentation, sandbox-compiled) and matrix hard-constraints (numeric boundaries on the objective, checked by the orchestrator's `constraintsSatisfied`, never sandbox-compiled) are separate flows; only the filter flow gets the richer ops.
- **Structured-output representation:** typed *in the strict schema*, not a JSON-string field, but on a **new, separate `filterItem` schema for the intervention-tree filters — the existing `constraintItem` (shared with `evaluationMatrixSchema`'s hard constraints) stays numeric-only.** This is load-bearing: `constraintItem` is used in BOTH `interventionTreeSchema` and `evaluationMatrixSchema`, and `evaluationMatrixWire.Constraints` decodes directly into `[]domain.Constraint` (`Value float64`); growing the shared `constraintItem` value would break `decodeMatrix` (a non-numeric matrix constraint fails the numeric unmarshal → 502) and let the model emit `eq`/`in` hard constraints. The filter value is shallow (a scalar or a flat set — no recursion, no per-dataset enum), so a bounded `anyOf` — pinned as `anyOf[{"type":"number"}, {"type":"string"}, {"type":"boolean"}, {"type":"array","items":{"anyOf":[number,string,boolean]}}]` — plus a small op enum (~8) is grammar-safe and needs no post-parse depth seam. This is the key contrast with the objective change, which needed the JSON-string escape *only* because its value was a recursive AST. **Fallback contingency:** if strict structured output rejects the scalar-union-with-array `anyOf` at integration, fall back to a JSON-string `value` on `filterItem` parsed + type-validated deterministically (the `expressionShapeGuide`/`decodeMatrix` pattern). Note this is a *distinct* decode path, not the primary one: the primary `filterWire` token-sniffs a bare JSON value (`5`, `"Europa"`, `["Europa","Mars"]`); the fallback delivers a JSON *string whose contents are* JSON (`"\"Europa\""`, `"[\"Europa\",\"Mars\"]"`), which must be unwrapped one level (unmarshal the string) *before* the token-sniff/parse. The `filterWire` seam makes the swap localized, but the fallback body is its own unwrap-then-parse.
- **Depth:** `defaultDepth = 4`, `defaultBreadth = 3`, no node cap. Improving-branch pruning bounds the fan-out below the ~120-node worst case in practice; the cost is accepted for deeper research. **`loopTimeout` must rise to match** — the loop is fully sequential (~120 sandbox executes + ~40 Xhigh proposal calls worst case), so the fixed `10*time.Minute` would flip deep runs to `RunFailed` on timeout even after streaming triplets; this plan raises it so a depth-4 run can actually reach `completed`.

## Pattern Survey

### Analogous Features
- `internal/domain/domain.go:110-128` — **the backward-compat template.** `Target` was extended additively: `Aggregation`/`Value` are `omitempty`, and `ValueExpression()` is an accessor that degenerates a legacy `{field, direction}` row to a synthesized `Expression`. Mirror this for `Constraint`: add new fields as `omitempty`, keep the legacy `{field, op, value}` numeric semantics intact, route consumers through an accessor, never write a custom `UnmarshalJSON`. `TestLegacyTargetRoundTrip` is the byte-identity precedent to replicate for legacy numeric constraints.
- `internal/domain/domain.go:145-149` — `LiteralValue` (`Number *float64` / `String *string` / `Bool *bool`, each `omitempty`, exactly-one-set) is the **directly reusable typed scalar** for a boolean/categorical filter value.
- `internal/sandbox/compile.go:254-330` `compileExpr` (esp. `ComparisonKind`, `:285-301`) — **the coercion engine to mirror in `compileFilters`.** It resolves a column via `columnCoarseType`, checks type compatibility, binds string/bool/number literals as `?` params via `literalValue`, and emits type-appropriate SQL. `compileFilters` (`:175-194`) currently does the opposite — flat-rejects any non-numeric column at `:183-185`.
- `internal/orchestrator/hypothesis.go:272-279` `writeTriplet` SSE publish — **the change-1 target.** `obj.label`, `obj.direction`, and `effective` (the cumulative filters) are all already in scope at the call site, so enrichment reads data already present; no new plumbing.
- `internal/llm/schema.go` `evaluationMatrixSchema` / the deleted `literalSchema` — **the loosening/typed-value precedent.** The objective `value` moved to a plain string only because it was recursive; the pre-`152c66c` `literalSchema` (a 3-way `number|string|bool` `anyOf` of closed objects) is the exact *bounded* value shape to re-introduce for the filter operand.
- `internal/llm/client.go` `decodeMatrix`/`evaluationMatrixWire` — **the wire-decode precedent.** A polymorphic structured-output body is decoded into a typed domain value via a private wire struct. The filter change adds an analogous `filterWire` (for the intervention filters only) mapping `(op, polymorphic value)` → typed `domain.Constraint`; `evaluationMatrixWire` stays numeric and untouched.
- `internal/llm/client.go` `expressionShapeGuide` — the prompt-grounding precedent: a constant appended to the system prompt that describes the typed shape the model must emit. The filter change adds a `filterShapeGuide` for op/value/column-type rules.

### Reusable Utilities
- `internal/domain/domain.go` `UnknownFilterColumns` — the CGO-free grounding pre-check is **already op/value-agnostic** (matches on `Field` only), so it keeps working unchanged for the richer filters. Consumed by `splitByColumns` (`hypothesis.go`).
- `internal/domain/domain.go` `ConstraintOps` var + `constraintOpEnum` (`schema.go`) — the single-source op-enum-var pattern the structured-output schema derives from (keeps enum and typed constants from drifting). `ConstraintOps` stays numeric (matrix); the new richer ops go in the new `FilterOps` var (Step 1), which the new `filterOpEnum` derives from.
- `internal/domain/domain.go` `RenderObjectiveLabel`/`renderExpr`/`renderLiteral` — the deterministic, dependency-free render precedent for a new `RenderConstraint` (used to render filter chips into the SSE payload and prompt summaries).
- `internal/sandbox/compile.go` `columnCoarseType`, `coarseType`, `literalValue`, `allowedCompareOp`, `quoteIdent`, `resolveColumn`, `isNumeric` — the coarse-type + injection-safety helpers `compileFilters` reuses verbatim.
- `internal/graph/neo4j.go` `marshalProps`/`unmarshalProps` — node properties (`new_filters`/`effective_filters`) serialize as a JSON string and read back as generic `map[string]any`, never re-decoded into `domain.Constraint`, so **graph-persisted filters are forgiving of the `Constraint` shape change**.

### Convention Anchors
- **Injection contract (sandbox):** ops come from allowlists; identifiers are schema-validated then `quoteIdent`-quoted; every upstream value is a bound `?` param, never interpolated. Boolean/categorical/set filter values MUST be bound (a set becomes `IN (?, ?, …)`), following `compileExpr`'s comparison, not string concat.
- **Type-check-up-front:** every compiler node rejects type-incompatible combinations before SQL runs (`errTypeIncompatible`, mapped 400). A `HomePlanet < 5` (numeric op on a string column) or `Age = 'young'` (string operand on a numeric column) must be rejected at compile time, the way `compileExpr`'s comparison enforces operand type-equality.
- **Additive/omitempty legacy compatibility:** legacy `{field, op, value}` numeric constraints live as jsonb in `goal_registry.evaluation_matrix` and as graph props; the change must keep them byte-identical on round-trip. Keep `Value float64` present (not omitempty — a threshold of exactly 0 is valid); add new value fields as `omitempty`.
- **Structured-output enum minimization:** keep the op enum bounded (~8 entries, far under the grammar ceiling); model the polymorphic value as a bounded `anyOf` (scalar variants + a flat array), never a per-dataset enum, never recursion.
- **Prompt-grounds-the-shape:** `interventionTreeSystem`/`interventionTreeRepairSystem` describe the filter shape; `filterSummary`/`matrixSummary` echo filters back via `%v` on `Value`. Both must learn the richer value model, à la `expressionShapeGuide`.
- **SSE serialization is passthrough:** `writeTriplet` builds a `map[string]any` marshaled by the hub; the Next.js BFF (`web/lib/proxy.ts` `forwardStream`, `web/app/api/orchestrator/goals/[id]/stream/route.ts`) streams the body byte-for-byte and `web/lib/sse.ts` parses whole `data:` frames. **No BFF/proxy change is needed** — only the Go payload map and the TS `TripletPayload` interface (`web/lib/orchestrator.ts:19-26`) + its two consumers (`EffectReadout.tsx`, `LiveRun.tsx`).
- **Tree defaults as named constants:** `defaultBreadth`/`defaultDepth` in `server.go:30-33` carry a `≈ breadth + breadth²` cost comment that goes stale at depth 4 (worst case ≈ breadth+breadth²+breadth³+breadth⁴).
- **Test placement mirrors `152c66c`:** `internal/sandbox/compile_test.go`, `internal/domain/domain_test.go`, `internal/llm/{schema_test.go,client_test.go}`, `internal/orchestrator/{hypothesis*,submit}_test.go` — the same blast radius the objective change touched.

### Proposed Alignment
Follow the `Expression`/`Target` precedent: extend `domain.Constraint` additively (keep numeric `{field, op, value}` for legacy jsonb; add a typed `Operand *LiteralValue` and `Members []LiteralValue` as `omitempty`, plus new `ConstraintOp` consts in the single-source `ConstraintOps` var; centralize interpretation in an accessor + a `RenderConstraint`). Make `compileFilters` coerce by mirroring `compileExpr`'s comparison node — coarse-type resolve, `allowedCompareOp`, bound literal, and a compile-time **coarse-type-equality** reject (the comparison node's `leftType != rightType` rule, `compile.go:297-299`) — instead of its current flat numeric reject, reusing `columnCoarseType`/`literalValue`. (Do NOT use `checkCastable` for the operand/column type match: it answers "can X cast to Y" and permits e.g. numeric→boolean, which is the wrong bar for a filter equality.) Leave `constraintItem` (shared with `evaluationMatrixSchema`'s numeric hard constraints) untouched; add a **new `filterItem`** for the intervention filters with a bounded `filterOpEnum` and a bounded `anyOf` value, and decode its polymorphic value into typed `domain.Constraint` via a new `filterWire` (à la `decodeMatrix`, but only for `proposalWire`); ground it with a `filterShapeGuide`. Enrich the `triplet` SSE payload from data already in `writeTriplet`'s scope; render segment chips + a direction-aware improvement label on the card. Bump the depth constant (and `loopTimeout`/`replayBufferSize` to match) and fix the cost comment.

## Implementation Steps

1. **Extend the `domain.Constraint` model with typed values, new ops, and an accessor** (`internal/domain/domain.go`)
   - Add `ConstraintOp` consts: `Equal ("eq")`, `NotEqual ("neq")`, `In ("in")`, `NotIn ("not_in")`. Keep the existing `ConstraintOps` var **numeric-only** (`lt`/`lte`/`gt`/`gte`) — it is the single source for the matrix hard-constraint schema enum, which must stay numeric (see Step 3, the `constraintItem`/`filterItem` split). Add a separate `FilterOps` var = the numeric ops **plus** `eq`/`neq`/`in`/`not_in`, the single source for the intervention-filter schema enum.
   - Extend `Constraint`: keep `Field string json:"field"`, `Op ConstraintOp json:"op"`, `Value float64 json:"value"` (unchanged — legacy numeric threshold, non-omitempty). Add `Operand *LiteralValue json:"operand,omitempty"` (typed scalar for `eq`/`neq`) and `Members []LiteralValue json:"members,omitempty"` (typed set for `in`/`not_in`).
   - Add a small op-classification helper (e.g. `IsNumericThresholdOp`/`IsEqualityOp`/`IsMembershipOp`, or one `OpClass` accessor) so consumers never hardcode the op sets, and a deterministic dependency-free `RenderConstraint(Constraint) string` (mirroring `renderExpr`/`renderLiteral`) that renders `field op value` / `field IN {a, b}` for the SSE payload and prompt summaries.
   - Backward-compat: legacy `{field, op, value}` round-trips byte-identical (`Operand`/`Members` omitempty → absent); a new `eq`/`in` constraint carries a harmless `value:0`.

2. **Teach the sandbox `compileFilters` to compile coerced boolean/categorical/set predicates** (`internal/sandbox/compile.go`)
   - Replace the flat non-numeric reject in `compileFilters` (`:183-185`) with an op-class switch:
     - numeric threshold (`lt`/`lte`/`gt`/`gte`): require a numeric column (as today), map via `allowedOp`, bind `Value`.
     - `eq`/`neq`: resolve `columnCoarseType`; bind the typed `Operand` via `literalValue` (already `func literalValue(l *domain.LiteralValue) (any, coarseType, error)`, so `Constraint.Operand *LiteralValue` passes verbatim — no new variant needed); type-check operand coarse type against the column (numeric↔numeric, boolean↔boolean, string↔string; reject temporal/mismatched at compile time via `errTypeIncompatible`); emit `quoteIdent(col) = ?` / `!= ?` with the bound literal.
     - `in`/`not_in`: type-check and bind each `Members` literal; emit `quoteIdent(col) IN (?, ?, …)` / `NOT IN (…)`. Reject an empty `Members` set at compile time.
   - Add an `allowedFilterOp` allowlist (or extend logic) keeping the injection contract — every value is a bound `?`. Note in a comment that `compileFilters` is shared by `compileQuery` (legacy) and `compileObjective`, so both execute paths gain the capability.
   - Reuse `columnCoarseType`, `literalValue`, `quoteIdent`, `resolveColumn`, `isNumeric` verbatim.

3. **Split the constraint schema, add the richer filter schema + wire decode, and ground the prompt** (`internal/llm/schema.go`, `internal/llm/client.go`)
   - **Keep `constraintItem` numeric-only and unchanged** — it is shared by `evaluationMatrixSchema` (`schema.go:71`, the matrix's hard `constraints`) whose `evaluationMatrixWire.Constraints` decodes directly into `[]domain.Constraint{Value float64}` (`client.go:159,187`). Growing it would break `decodeMatrix` for any non-numeric matrix constraint (→ 502) and leak the richer ops into hard constraints. `constraintOpEnum()` stays derived from the numeric `ConstraintOps`; `evaluationMatrixWire` and `decodeMatrix` are untouched.
   - **Add a new `filterItem()` builder** for `interventionTreeSchema` (`schema.go:84`, the candidate `filters`): `field` a `stringProp()`; `op` an `enumSchema(filterOpEnum())` where `filterOpEnum()` derives from the new `FilterOps` var (~8 entries, far under the grammar ceiling); and a bounded `value` pinned as `anyOf[{"type":"number"}, {"type":"string"}, {"type":"boolean"}, {"type":"array","items":{"anyOf":[{"type":"number"},{"type":"string"},{"type":"boolean"}]}}]` (a scalar union plus a flat typed array — non-recursive, no per-dataset enum). Point `interventionTreeSchema` at `filterItem()`; leave `evaluationMatrixSchema` on `constraintItem()`. Confirm `TestSchemaWidthIndependent` still holds. (Fallback per the Decisions note: if strict output rejects this `anyOf`, make `filterItem`'s `value` a `stringProp()` carrying a JSON-encoded typed value, parsed in the wire decode below.)
   - `client.go`: add a private `filterWire` (field, op, `value json.RawMessage`) and a decode that **sniffs the raw JSON token** of `value` (since `domain.LiteralValue` is an object and cannot unmarshal a bare scalar): a JSON `number`/`string`/`bool` → for threshold ops set `Value` (numbers only) else set `Operand` = `LiteralValue{Number|String|Bool}`; a JSON `array` → set `Members` = `[]LiteralValue`. Map to typed `domain.Constraint` and wire it into `proposalWire`'s filter decode used by `ProposeInterventionTree` and `RepairInterventionTree`. A malformed/type-mismatched wire value is a generation error (the existing proposal parse-failure path). `evaluationMatrixWire` is NOT changed.
   - Add a `filterShapeGuide` constant (à la `expressionShapeGuide`) stating the op/value rules by column type — numeric → `lt/lte/gt/gte` + number; boolean → `eq/neq` + true/false; categorical/string → `eq/neq/in/not_in` + string(s) — and append it to `interventionTreeSystem` + `interventionTreeRepairSystem` only. Update `filterSummary` and `matrixSummary` to render via `domain.RenderConstraint` instead of `%v` on `Value`. `RepairInterventionTree` currently echoes the rejected candidates via `json.Marshal(prior.Candidates)` (raw `domain.Constraint` internal shape — `{…, value:0, operand:{string:"Europa"}}`), which diverges from the flat `filterItem` `value` the model must emit; render that echo via `domain.RenderConstraint` (or the wire shape) so the repair prompt shows the same shape the output schema demands. Low-impact (the repair only fixes column names) but keep it consistent.

4. **Enrich the triplet SSE payload, guard `constraintsSatisfied`, and deepen the tree** (`internal/orchestrator/hypothesis.go`, `internal/orchestrator/server.go`)
   - `writeTriplet` SSE publish (`:272-279`): add `objective_label` (`obj.label`), `direction` (`obj.direction`), and `filters` — the `effective` segment rendered via `domain.RenderConstraint` (a `[]string` of predicate chips). Optionally also `new_filters` (this candidate's added filter) so the card can distinguish the segment from the delta; keep both if cheap.
   - `constraintsSatisfied` (`:462-487`): **no change strictly required** — after the schema split, matrix hard constraints are numeric-only end-to-end (the numeric `constraintItem` + untouched `evaluationMatrixWire`), so a non-numeric op can't reach this switch, and even if it did the switch has no `default` and falls through to `return true` (unmatched op → satisfied). Optionally add an explicit belt-and-suspenders comment/case documenting that non-numeric ops on the objective aggregate are unverifiable→satisfied, but do not frame it as load-bearing. `objectiveField` is unchanged.
   - `server.go` `defaultDepth`: `2 → 4`. Update the stale cost comment to reflect the `breadth + breadth² + breadth³ + breadth⁴` worst case and that improving-branch pruning bounds it in practice.
   - **Raise `loopTimeout`** (`hypothesis.go:30`, currently `10*time.Minute`) to fit the depth-4 sequential fan-out: the loop runs one sandbox `Execute` per node plus one `Xhigh`+adaptive-thinking `ProposeInterventionTree` per improving internal node, all sequentially, so a broad depth-4 tree can exceed 10 minutes and the defer would flip an otherwise-progressing run to `RunFailed` (`termErr = ctx.Err()`, `hypothesis.go:98-107`). Raise it to a value that lets a realistic depth-4 run complete (e.g. `30*time.Minute`; the implementer tunes against an observed run), and note the timeout↔depth tradeoff in the constant's comment. Without this the plan's "reaches `completed`" verification cannot hold.
   - **Raise `replayBufferSize`** (`internal/orchestrator/hub.go:7`, currently `64`) to cover the depth-4 worst-case event count (`≈ breadth+breadth²+breadth³+breadth⁴ = 120`, plus branch-failure/loop-complete frames). At depth 2 the ~12-event worst case always fit the ring; at depth 4 a mid-run SSE reconnect (`LiveRun.tsx` `RECONNECT_MS`) would replay only the last 64 events, dropping the earliest triplets from the feed — and the longer `loopTimeout` widens the reconnect window. Bump the ring to ≥ the worst case (e.g. `256`) so a reconnecting client still replays the full run; update the constant's comment.

5. **Surface the segment + direction on the web triplet card** (`web/lib/orchestrator.ts`, `web/components/EffectReadout.tsx`, `web/components/LiveRun.tsx`)
   - `orchestrator.ts` `TripletPayload` (`:19-26`): add `objective_label: string`, `direction: "maximize" | "minimize"`, and `filters: string[]` (the rendered segment chips), matching the Go payload keys.
   - `EffectReadout.tsx`: render the `filters` as a compact predicate chip list (the segment this triplet measured) and use `direction` to color/label improvement correctly — a delta that moves the objective in the desired direction is the positive/green case (for `minimize`, a *negative* delta is the improvement), replacing the current "positive delta = green" assumption its own comment flags. Keep the diverging-bar normalization.
   - `LiveRun.tsx`: thread the new fields through the `FeedItem`/`TripletPayload` usage (`:38`, `:113-114`); no proxy/BFF change (SSE passthrough).

6. **Tests across the blast radius** (see Verification for the matrix)
   - `internal/domain/domain_test.go` — legacy numeric `Constraint` round-trips byte-identical; new `eq`/`neq` (bool + string) and `in`/`not_in` (set) round-trip; `RenderConstraint` output; op-class accessor.
   - `internal/sandbox/compile_test.go` — boolean `eq`, string `eq`/`neq`, `in`-set, `not_in`; numeric threshold still compiles; type-mismatch (`Age = 'young'`, `HomePlanet < 5`, empty `in` set) rejected with `errTypeIncompatible`/400; injection safety (values bound, not interpolated).
   - `internal/llm/schema_test.go` — the new `filterItem` op enum is the richer `FilterOps` set, its value is the pinned bounded `anyOf` (no per-column enum); `constraintItem` (matrix) is unchanged (numeric op enum, numeric value); `TestSchemaWidthIndependent` intact.
   - `internal/llm/client_test.go` — the `filterWire` decode maps a proposal mixing threshold/eq/in filters into typed `domain.Constraint` (scalar-token→Operand, array-token→Members, number+threshold→Value); the intervention prompt embeds `filterShapeGuide`; `RepairInterventionTree` round-trips the richer filters. **Add a guard that `decodeMatrix`/`evaluationMatrixWire` still decodes a numeric matrix hard-constraint unchanged** (the P1 regression the split prevents).
   - `internal/orchestrator/{hypothesis,submit}_test.go` — the triplet SSE payload includes `objective_label`/`direction`/`filters`; `constraintsSatisfied` skips non-numeric objective constraints (treated satisfied) while numeric cases stay exact.
   - `web` — if a component test harness exists, assert the card renders chips + direction-correct coloring; otherwise cover via the live E2E.
