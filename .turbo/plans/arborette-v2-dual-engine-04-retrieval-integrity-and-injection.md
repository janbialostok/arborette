# Plan: Heuristic-Retrieval Integrity & Injection Hardening

## Context

In V2 the Meta-Heuristic corpus stops being a browsing surface and becomes machinery: retrieval seeds MCTS grounding moves and priors, and heuristic content influences what gets verified and searched. Two measured drift/abuse paths therefore get teeth: an unbounded k-NN that returns the whole corpus ranked however distant (and, live-measured, a corpus that was 92% invisible after embedding drift), and prompts that interpolate untrusted goal text/definitions with no fencing — a stored-injection vector that now steers search and verification. This plan closes both halves: retrieval becomes goal-scoped with a calibratable distance floor, the resume pass widens into a reconcile pass, and all untrusted prompt interpolation gets per-request random fencing with shape checks.

Covers spec requirements R25 (goal-scoped retrieval + distance floor), R26 (reconcile pass), R29 (prompt fencing + definition shape checks).

**Settled decision:** the distance floor ships **enabled at 0.5** (`EMBEDDING_DISTANCE_FLOOR`, env-tunable), matching the ~0.48–0.50 floor value that the ~0.05 margin measured 2026-07-28 suggests. Recalibration against the R30 dataset (spec `.turbo/specs/arborette-v2-dual-engine.md:177`) happens when that dataset lands; this default is provisional, not a contract.

**Design decision (goal provenance for reconcile):** Meta-Heuristic graph nodes today carry no goal id — `derivedID` namespaces are one-way hashes, so the goal of an existing node is unrecoverable. The reconcile pass and resume pass therefore need the graph to record `goal_id` on MH nodes at write time. Legacy nodes (and rows re-embedded from them) get a NULL `goal_id`, meaning "visible only to cross-goal queries" until healed. The heal is a two-hop chain and **must reach the Postgres column scoped search actually filters on**: (1) the goal's next abstraction run re-MERGEs the node with a goal (the relink path), populating the graph property; (2) the next reconcile pass propagates any node whose graph `goal_id` is populated but whose pgvector row still has NULL into the row via a cheap goal-repair `UPDATE` (no re-embed — the vector is unchanged). Without hop 2 the already-embedded legacy corpus would stay goal-invisible forever, since the relink branch never re-upserts and reconcile's re-embed arm only covers missing-or-pending rows. Consistent with the existing nil-vs-`""` audit discipline throughout.

**Plan risk (downstream compatibility):** Shell 06 (grounding) consumes retrieval in explicit cross-goal mode and Shells 06/08 add the four new LLM calls that must adopt the fencing helper. The seams built here — a `SearchScope` value on the query path and an exported fencing helper in `internal/llm` — are the stable contracts those shells build on; keep both exported and documented.

### Convention Anchors
- Prompt construction centralizes in `internal/llm`: each `client` method builds a user prompt + a `const …System` string + a schema, then calls `backend.complete`. The fencing helper belongs in `internal/llm` so `client.go`'s builders and the orchestrator both consume one implementation.
- Untrusted-text handling: only `orchestrator/chat.go` fences today. The verified rule: mint per request via `crypto/rand.Text()`; test against reused **and nested** markers (single-pass stripping is defeatable by a marker nested inside itself). `internal/orchestrator/chat_test.go:408-460` is the reference test shape (fence present, untrusted text cannot close it).
- Config: env parsing lives in `internal/config/config.go` with per-service typed sub-structs. The distance-floor knob belongs in `EmbeddingConfig` (shared by read + write sides).
- Migrations: numbered `NNNN_name.up/.down.sql`, embedded via `//go:embed *.sql`, grants written in-file against the two runtime LOGIN roles, never `CREATE ROLE`. A goal_id ALTER needs no new grants (roles already hold SELECT/INSERT/UPDATE/DELETE on the table via 0005/0008).
- Store methods: parameterized SQL only, errors wrapped `fmt.Errorf("…: %w", err)`; `Upsert` uses `ON CONFLICT (node_id) DO UPDATE`.
- Interfaces defined at the consumer: `heuristics.embeddingStore`/`heuristicRepo` (`internal/heuristics/service.go:35-46`) and the sleepcycle worker interfaces (`internal/sleepcycle/worker.go:83-117`). Goal-scoped search and the reconcile diff widen these consumer interfaces, not just the concrete types.
- Audit/reporting for resume-like passes: `w.report(ctx, "sleepcycle_resume_failure"|"sleepcycle_relink_failure"|"sleepcycle_heuristic_injection", …)` with `map[string]any` detail carrying `optimization_function_id` (nil, not `""`, when the pass names no goal) and `meta_heuristic_id`. The reconcile pass emits analogous events with the same nil-vs-empty discipline.
- goalID flows as a plain `string` through `Worker.Run` → `searchTarget.goalID` → `abstractAll` → `embed(ctx, goalID, …)`. It already reaches `embed` but is discarded at the store boundary, and `resumeEmbeddings` passes `""`. Threading goal_id into `Upsert` (and onto the MH graph node) closes that gap.

### Proposed Alignment
Blend, leaning heavily on reuse. Extract `chatContextMarkers` + the "content is data" preamble from `internal/orchestrator/chat.go` into a shared helper in `internal/llm`, then apply it at the currently-unfenced sites in `client.go`/`abstract.go`; the per-request `rand.Text()` discipline and its test shape already exist to copy. The definition length/shape check extends `decodeAbstraction`, mirroring its existing empty-definition rejection and `LeakedConcreteTerms`. Retrieval changes follow the store/config conventions (goal_id via an ALTER migration in the `0011` slot, distance floor as an `EmbeddingConfig` knob, both threaded through the consumer-defined interfaces). The reconcile pass slots into `Run` beside where `resumeEmbeddings` sits, using the same `w.report` audit discipline — with two genuinely new primitives (no analog exists): a graph query listing all MetaHeuristic refs and a store query listing all embedding node_ids.

## Implementation Steps

1. **Migration 0011: `goal_id` on embedding rows**
   - Add `internal/store/migrations/0011_embedding_goal_scope.up.sql`: `ALTER TABLE meta_heuristic_embeddings ADD COLUMN goal_id uuid` (nullable — legacy rows stay NULL and are matched only by cross-goal queries), plus a btree index on `goal_id` for the scoped filter. The type is pinned to `uuid`: goal ids are `goal_registry.optimization_function_id uuid` (`0002_goal_registry.up.sql:2`) and `node_id` is already `uuid`. No new grants needed (0005/0008 already cover the table). Write the paired `.down.sql` dropping index + column.
   - No backfill: goal provenance for existing rows is unrecoverable from Postgres (see Context); reconcile + later abstraction runs heal them.

2. **Thread `goal_id` through the write path and onto the graph node**
   - `internal/store/embeddingstore.go`: widen `Upsert` to `Upsert(ctx, nodeID, goalID string, embedding []float32)`; empty `goalID` writes SQL NULL (mirror the nil-vs-`""` discipline). Update the `ON CONFLICT` clause with `goal_id = COALESCE(EXCLUDED.goal_id, meta_heuristic_embeddings.goal_id)` — a re-embed under a known goal repairs a NULL row, while a goal-less caller (reconcile/resume of a legacy node) can never re-blank a populated one, mirroring the graph-side guard below.
   - `internal/domain/domain.go:131-136`: add `GoalID string` to `domain.MetaHeuristic`.
   - `internal/graph/neo4j.go`: `CreateMetaHeuristic` (`:292`) sets a `goal_id` property on the node. The Cypher must **never overwrite a populated `goal_id` with an empty one**: `ON CREATE SET` includes `m.goal_id = $goalID` unconditionally; the conditional match-side write is a **standalone `FOREACH` clause** — `FOREACH (_ IN CASE WHEN $goalID <> '' THEN [1] ELSE [] END | SET m.goal_id = $goalID)` — placed **after** the MERGE/ON CREATE/ON MATCH block and **before** the `WITH m UNWIND $ids` edge chain (`neo4j.go:320-329`), because `ON MATCH SET` accepts only set-items (FOREACH cannot be embedded in it) and placing it after the UNWIND would run it per-edge instead of once. The params map at `:328` gains the `"goalID"` key. Net effect: legacy nodes heal on re-abstraction while a goal-less caller (reconcile/resume) can never re-blank a scoped node. `GetMetaHeuristic`, `GetMetaHeuristics` (`:179`), and `ListEmbeddingPending` (`:353`) return it (absent property → `""`).
   - `internal/sleepcycle/worker.go:107-109`: widen the `embeddingStore` consumer interface's `Upsert` accordingly; `internal/sleepcycle/abstract.go:160-185` `embed` passes its `goalID` through; `abstractOne` sets `GoalID: target.goalID` on **both** of its `domain.MetaHeuristic` constructions — the relink call for an existing node (`internal/sleepcycle/abstract.go:70`) and the fresh-create call (`:105`). The relink site is the healing opportunity for legacy nodes (it runs on every steady-state re-selection), so leaving it zero-valued would defeat the heal path; `resumeEmbeddings` passes `mh.GoalID` instead of `""`.
   - Fix the test fakes in `internal/sleepcycle/*_test.go` that implement `embeddingStore`.

3. **Goal-scoped `SimilaritySearch` with the distance floor**
   - `internal/config/config.go`: add `DistanceFloor float64` to `EmbeddingConfig` (`:71-76`), loaded as `floatEnv("EMBEDDING_DISTANCE_FLOOR", 0.5)` next to `Dimension` (`:303-305`). Validate `0 < floor <= 2` (cosine distance range) via a standalone `store.ValidateDistanceFloor(floor float64) error` called from each `cmd/` startup right beside the existing `ValidateEmbeddingDimension` call — **not** by giving `NewEmbeddingStore` an error return; the constructor stays error-free and its signature change stays mechanical.
   - `internal/store/embeddingstore.go`: `NewEmbeddingStore(pool, distanceFloor float64)`; define `type SearchScope struct { GoalID string; CrossGoal bool }` and change `SimilaritySearch` to `SimilaritySearch(ctx, query []float32, k int, scope SearchScope)`. Reject a scope with neither/both fields set (exactly one mode). Build the SQL by mode rather than one OR-ed clause — the `goal_id` column is `uuid`, and binding a Go `""` against a uuid parameter fails at bind time regardless of runtime short-circuiting: goal-scoped mode runs `… WHERE (embedding <=> $1) <= $floor AND goal_id = $goalID …`; cross-goal mode omits the goal predicate entirely (`… WHERE (embedding <=> $1) <= $floor …`). Cross-goal thereby matches NULL-goal legacy rows; goal-scoped does not.
   - **Recall contract under filtering:** hnsw serves `ORDER BY embedding <=> $1 LIMIT k` from a bounded candidate neighborhood and applies the goal/floor predicates as post-filters, so a goal-scoped query over a corpus dominated by other goals could silently return fewer than k matching rows — the same invisibility class this plan exists to close. Run each `SimilaritySearch` inside a transaction that first issues `SET LOCAL hnsw.iterative_scan = relaxed_order`, making the scan continue past filtered-out candidates. **Version reality:** `hnsw.iterative_scan` landed in pgvector **0.8.0** (not 0.7), and `docker-compose.yml:41` currently floats on the unpinned `pgvector/pgvector:pg16` tag — pin it to a ≥ 0.8.0 tag (e.g. `pgvector/pgvector:0.8.0-pg16`) and add a startup probe `store.ValidateVectorExtensionVersion` beside `ValidateEmbeddingDimension` that reads `SELECT extversion FROM pg_extension WHERE extname = 'vector'` and **parses major.minor as integers** (never lexical string compare — `"0.10.0" < "0.9.0"` lexically) requiring ≥ 0.8, so a stale local image fails one clear startup error instead of failing every search at runtime. The contract to document on the method: a scoped search returns min(k, all rows of that goal within the floor) **up to the `hnsw.max_scan_tuples` bound (default 20000 tuples scanned)** — exhaustive at expected corpus scale; revisit that GUC together with the floor calibration if the corpus ever approaches the bound.
   - `internal/heuristics/service.go`: widen the `embeddingStore` consumer interface (`:35-38`) and `Query` (`:72`) to accept a `store.SearchScope` (or a mirrored local type), passed through to the search. `retireOrphans` and its "table does not carry a goal" comment (`:117-120`) stay as-is this shell — read-side retirement narrowing is not in scope.
   - Callers make their mode explicit: `internal/orchestrator/heuristics.go` `handleHeuristicSearch` reads an optional `goal_id` query param — present → goal-scoped, absent → explicit `CrossGoal: true` (the browsing surface's deliberate choice); `internal/mcpserver/tools.go` `getOptimizedHeuristics` gains an optional `goal_id` input field with the same rule (keep the field description analyst-safe). The `Query` widening also compile-breaks the `heuristicsQuerier` consumer interface at `internal/mcpserver/tools.go:43-44` and `fakeQuerier.Query` at `internal/mcpserver/tools_test.go:26` — widen both alongside.    - Signature blast radius beyond `cmd/` and the sleepcycle fakes: `internal/heuristics/heuristics_test.go` (`NewEmbeddingStore` at `:38`, `Upsert` at `:58`, the `fakeEmbeddings.SimilaritySearch` method at `:131`), `internal/store/store_test.go` (`NewEmbeddingStore` at `:44`, `:87`, `:573`, `:595`; `Upsert` at `:48`, `:93-99`, `:575-592`; `SimilaritySearch` at `:103`), and `internal/mcpserver/tools_integration_test.go` (`NewEmbeddingStore` at `:40`, `Upsert` at `:58` — `package mcpserver` with no build tag, so it compiles under plain `go test ./internal/mcpserver/...`) must all be updated in the same change.
