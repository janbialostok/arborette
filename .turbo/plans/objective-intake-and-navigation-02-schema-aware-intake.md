# Plan: Schema-Aware Objective Intake

## Context

The evaluation matrix is generated from goal text alone, blind to the dataset, so an analyst must phrase the objective to match a column name and case exactly or the run fails. This shell makes registration fit the objective to the dataset: introspect the source first, hand Claude the schema, and have it resolve the objective to real columns (case-insensitive and semantic) as a structured expression + aggregation + direction. Because the fitted objective now carries its aggregation, run-time objective selection moves out of the root hypothesis-tree proposal and into the matrix; the loop's `pinObjective` reads the matrix, and a legacy matrix with no aggregation is surfaced as a clear terminal failure directing re-registration rather than silently mismeasured. Registration also validates the fitted objective against the schema and attempts a single schema-aware repair before failing with an actionable message — so a persona who never opened the dataset can still register a valid goal.

**Decisions locked at expansion (were open questions):**

- **Column matching — enum-constrained, model-only.** The value-expression's `ColumnRef` `column` field (and the target `field`, and constraint fields) are constrained in the structured-output schema to the introspected column-name enum (`columnEnum(schema)`), so the model literally cannot emit a mis-cased or nonexistent column — column validity is guaranteed *by construction*, and case-insensitive matching (R2) becomes moot. Semantic intent→column mapping ("transported passengers" → the `Transported` column) is left to the model, which now has the schema in context. No deterministic normalization/fuzzy guard is added.
- **Objective validation — dry-run via the sandbox.** Rather than hand-restating the sandbox's coarse-type rules orchestrator-side (which `CGO_ENABLED=0` would force to be a drift-prone copy of `compile.go`), intake validates the fitted objective by executing it against the sandbox with no filters — the same `ExecuteRequest` the root baseline will run. A `200` means the objective compiles and measures; a `400 {error}` is the exact, authoritative validation message. This reuses `pinObjective(matrix)` so validation pins the objective identically to run time, and it needs no second coarse-type implementation.
- **Repair — one retry, error fed back.** On a `400`, the orchestrator calls a dedicated `RepairEvaluationMatrix(ctx, goalText, schema, prior, validationErr)` that re-generates the matrix with the prior fitted matrix and the sandbox's validation error embedded in the prompt, then re-runs the dry-run **once**. Still failing → registration fails with the actionable message.

**New seam introduced (partial overlap with shell 03 — reconcile at 03's expansion):** the dry-run requires the orchestrator's sandbox client to parse the sandbox's `{error}` body instead of collapsing every non-`200` to `sandbox /execute returned status N`. This shell adds that parsing (a typed `SandboxError{Status, Message}`) because the dry-run's repair loop needs the real `400` message. Note this is not purely a downstream *consumption*: shell 03's own Produces currently lists "the Orchestrator's sandbox client parses the sandbox's `{error}` body" — so the parsing is claimed by both shells. Building it here is justified (this shell is where it is first needed); when shell 03 is expanded, its Produces should be reconciled to keep only the `branchFailure`/run-row wiring layered on top of the already-built `SandboxError`, dropping the body-parsing clause. No redesign is forced — 03 consumes a finished seam — but the overlap is real and must be reconciled rather than double-implemented.

**Primary implementation risk (verify first):** the value expression is a recursive discriminated union (`domain.Expression`), and this shell asks the model to emit it under a structured-output JSON schema with an **enum on a nested `column` field**. Structured-output support for (a) a self-referential/recursive schema, (b) enum constraints on nested AST fields, and (c) the union representation (`oneOf` per kind vs. a single fat-node object with only `kind` required) is the one unproven assumption. The default is a **bounded-depth, non-self-referential** schema built by a Go-side recursive builder (objective expressions are shallow — `avg(CASE WHEN col = 'x' THEN 1 ELSE 0 END)` is depth 3), which sidesteps recursion support entirely; confirm the union+enum representation against the Anthropic structured-output contract (consult the `claude-api` skill / the `anthropic-sdk-go` binding notes) before finalizing the schema shape, and fall back to a deterministic normalization guard only if enum-on-nested proves unsupported.

- `internal/orchestrator/sandboxclient.go:113` — `post` — the shared non-`200` handler that today returns `sandbox %s returned status %d` (`sandboxclient.go:130`); extended to decode the `{error}` body into a typed `SandboxError`.

### Convention Anchors

- **Structured-output schema shape**: every object is `object(props{...}, requiredKeys...)` with `additionalProperties:false`; enums are `{"type":"string","enum":[...]}`; column/objective enums derive from live data (`columnEnum`) or domain constants (`aggregationEnum`), never hardcoded. `schema_test.go` asserts `additionalProperties==false`, the `required` set, and enum contents — new AST/matrix-schema tests follow that shape.
- **Consumer-defined narrow interfaces**: `claudeClient`/`sandboxExecutor` (`server.go:43-51`) are defined at the orchestrator, satisfied by concrete `*llm.Client`/`*SandboxClient`. The `GenerateEvaluationMatrix` signature change and the new `RepairEvaluationMatrix` ripple: interface (`server.go:44`) → concrete method (`client.go:61`) → fake (`server_test.go:87`).
- **Error→HTTP-status mapping**: sentinel `errors.New` vars mapped in one `switch errors.Is(...)` (`submit.go:28-33,178`). Validation/precondition failures are 400; upstream Claude failures are `502` (`submit.go:61`); masked internals 500. New intake failures (introspection precondition, dry-run validation) add sentinels and slot into `writeIngestErr` or a sibling mapper. Today introspection failure is *logged only* (`submit.go:75`) — making it fatal is a behavior change at the same site.
- **Wire-DTO duplication (CGO constraint)**: `sandboxclient.go:19-26` documents that the orchestrator MUST NOT import `internal/sandbox` (blank-imports the CGO DuckDB driver; breaks `CGO_ENABLED=0` distroless-static). This is *why* the coarse-type validator is not restated orchestrator-side — the chosen dry-run delegates type-checking to the sandbox, avoiding the drift risk a hand-copied `compile.go` would carry.
- **No existing retry/repair loop**: a grep across `internal/` finds none; the single schema-aware repair is a net-new pattern with no prior art to mirror — designed here as one bounded retry, error fed back through a dedicated method.

### Proposed Alignment

The existing patterns were built in anticipation of this work: the `Expression` AST, `Target.Value/Aggregation` (additive/omitempty), `RenderObjectiveLabel`, the `ValueExpression`/`ObjectiveLabel` wire fields, and the sandbox's `compileObjective` path already exist and round-trip in tests, so steps 2/5 are mostly wiring the orchestrator to an already-finished server contract. Build the bounded-depth Expression schema and the enum-constrained column/target/constraint fields with the existing `object`/`props`/`fieldProp`/`columnEnum` kit and add symmetric `schema_test.go` assertions. Delegate all coarse-type validation to the sandbox via the dry-run (no orchestrator-side type rules). The two net-new pieces — the bounded-depth union schema and the one-shot repair loop — carry the risk and get the most test coverage.

## Implementation Steps

1. **Add the bounded-depth Expression schema + extend the matrix schema (`internal/llm/schema.go`).**
   - Add `func expressionSchema(cols []any, depth int) map[string]any` — a Go-side recursive builder producing the `domain.Expression` union as a bounded, non-self-referential structured-output schema. At `depth == 0` only leaf kinds are allowed (`ColumnRef` with `column: fieldProp(cols)`, `Literal`); each deeper level adds the composite kinds (`Cast`, `Comparison`, `Arithmetic`, `Case`) whose child expressions reference `expressionSchema(cols, depth-1)`. Match `domain.Expression`'s json tags (`kind`, `column`, `literal`, `operand`, `cast_type`, `op`, `left`, `right`, `cases`, `else`) and `LiteralValue`/`CaseBranch` shapes (`domain.go:145,152,164`). **Union representation:** confirm structured-output support first (see Context risk); default to a single fat-node object with `kind` (enum of the allowed kinds at this depth) as the only required key and all node subfields optional, or `oneOf` per-kind variants if the strict contract requires every property in `required`. Use a small `maxExprDepth` constant (≈3–4).
   - Change `evaluationMatrixSchema()` → `evaluationMatrixSchema(schema SandboxSchema)`. The `targets` item becomes `object(props{"field": fieldProp(columnEnum(schema)), "direction": enumSchema(directionEnum()), "aggregation": enumSchema(aggregationEnum()), "value": expressionSchema(columnEnum(schema), maxExprDepth)}, "direction","aggregation","value")` — **`field` is a property but NOT required.** A compiled expression has no single column name (`Target.ValueExpression()` ignores `Field` when `Value` is set, `domain.go:123`), and the spec/data-model treat `field` as optional (`targets: [{ field?, … }]`, R5), so forcing a required `field` would make the model invent an arbitrary single column for a multi-column `CASE`/comparison objective. The authoritative measured value is `value`; `field` stays available for a plain-numeric objective's readability/provenance. **Caveat to handle in step 2's prompt work:** `matrixSummary` (`client.go:194-198`) prints `direction`+`field` per target and would render a blank field for a compound objective — switch that summary line to `RenderObjectiveLabel(t.Aggregation, t.ValueExpression())` so the matrix overview stays legible. Enum-constrain `constraints` too now that the schema is available: `arrayOf(constraintItem(columnEnum(schema)))` (was `constraintItem(nil)`).
   - Update `schema_test.go` (matrix-schema tests) to assert the new required set, the aggregation/column enums, and the presence/shape of the `value` sub-schema.
