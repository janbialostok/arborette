# Plan: Verifier Service & Autonomous Causal Discovery

## Context

This shell births Engine B's home and its first stage: the `cmd/verifier` service and the autonomous causal-discovery pipeline. Discovery is the reframe at V2's center — the system infers the causal graph from the source data itself (CI tests own edge existence; Claude orients only what statistics cannot; analysts can correct later but never gate). It also ships the bundled ground-truth dataset, because discovery accuracy is only measurable against a known planted graph — the dataset is this shell's regression fixture and every later shell's demo substrate.

Covers spec requirements R4, R5, R6, R24 (partial: Verifier serve mode + launcher-seam invocation), and R30 (partial: ground-truth dataset creation, discovery-accuracy fixtures, and Engine A exercisability at defaults).

**Decisions settled at expansion** (from the spec's Open Questions, answered 2026-08-03):

- CI-test significance: **α = 0.05 with Benjamini–Hochberg FDR correction** applied per sweep level; both α and the correction choice are config knobs.
- Conditioning-set bound: **2**. Quantile bin count for mixed/numeric hybrid tests: **4** (quartiles). Both config knobs.
- Column cap default: **50**, configurable (mirrors the value-grounding cap knob convention).
- Sandbox `/analyze` gets its **own rate/concurrency class** under the per-class limiter (the `limiter.go` comment anticipates exactly this).

**Plan risks noted during expansion:**

- No `pg_advisory_lock` prior art exists anywhere in the repo — the cross-process single-flight is net-new design (the in-process mutex inflight-set in `internal/sleepcycle/server.go:99` is the only analogue and does not generalize across processes).
- No statistics library is in `go.mod` (no gonum). Chi-square/G-test p-values and Fisher-z partial-correlation tests need a small pure-Go stats module (regularized incomplete gamma + normal tail via `math.Erfc`) validated against reference values — adding gonum for two special functions is not warranted.
- `internal/domain/domain.go`'s `EpistemicSource` enum has only `observational`/`interventional` today; `causal_inferred` stays reserved for Shell 7's verification records — this shell adds graph-edge **provenance** (`statistical`/`llm_prior`/`analyst`), which is a separate axis from epistemic source. Do not conflate them.
- Downstream seam: Shell 7 (verification/refutation) consumes the persisted graph and the Verifier service scaffold; Shell 8 (router) consumes the orchestrator read endpoint. Keep the graph read DTO and the `POST /verifications` request shape additive-friendly (kind discriminator field) so Shell 7 extends rather than redesigns.

## Implementation Steps

1. **Create the bundled ground-truth dataset**
   - Write a deterministic generator `internal/verifier/groundtruth/generate.go` (seeded `math/rand.New(rand.NewSource(...))`, fixed seed constant) producing ~2,000 rows over a mixed-type schema with the planted structure required by R30: a confounder `Z → X, Z → Y` (making `X–Y` spuriously correlated), a true effect `A → Y` that survives adjustment, and an interaction effect `B×C → Y` that only conjunction search finds. Include at least one categorical, one boolean-like, and several numeric columns so all three CI-test kinds (chi-square/G-test, partial correlation, binned hybrid) are exercised. Export the ground-truth adjacency as a Go value (`groundtruth.Graph()`) for the regression tests.
   - **Support-density constraint (the CSV freezes here and later shells calibrate against it).** The recorded failure mode to design against: the bundled orders.csv cannot demo Sleep-Cycle Phase 2 because default `MinSupport` (30) empties the candidate union. Pin the generator so planted segments clear default floors: `B` and `C` are low-cardinality (2–3 levels each) with the interaction cell `B=b∧C=c` holding **≥ 3× default MinSupport rows** (≥100 of ~2,000) and a material `Y` delta (≥ ~0.5σ) so it survives support-shrunk ranking as a Phase-2 winner; single-column segments over `A`/`Z` likewise clear the floor. Encode these floors as generator-test assertions (count the cells in the emitted rows) so a reseed can't silently break the frozen fixture's R30/R14-calibration duty. Guard the **CI-power invariants** the same way — the discovery regression's headline assertions (confounded `X–Y` removed at level 1; `A → Y` survives) depend on association magnitudes, not just cell counts — with generator-test floors on the emitted rows: minimum marginal `X–Y` association induced by `Z` (so the spurious edge exists at level 0), maximum `X–Y` partial association given `Z` (so level 1 removes it), and minimum `A–Y` partial association given the other parents (so the true edge survives). Compute these directly from the generated rows in the test; a reseed that preserves counts but flips a discovery assertion now fails at the generator, not in a later shell.
   - Add a small `go:generate`-style entry point (`internal/verifier/groundtruth/cmd/gen/main.go` or a test helper writing via flag) that renders the CSV; commit the generated CSV as `local-import/causal-demo.csv` plus `local-import/causal-demo.md` documenting the planted graph, column semantics, and effect sizes.

4. **Implement the CI-test sweep and skeleton construction**
   - **Contract invariant (checked before implementing and again in review): the statistical layer must be total and deterministic.** Every combination of (endpoint-type pair × conditioner-type multiset × level 0..`DiscoveryMaxCondSet`) maps to exactly one test route with one defined statistic, p-value, and `n`/df accounting; every request shape a route emits fits the `/analyze` DTO caps at the *configured* bounds (caps derive from config, e.g. `2 + DiscoveryMaxCondSet`, never hardcoded literals); and every tie or selection among equals (separating sets, column ordering, stratum ordering) has a pinned tiebreak. Worked failures this invariant exists to prevent: the round-2 pooling rule left mixed *endpoints* unrouted at levels ≥1; route (c) left bin-vs-partial for numeric conditioners ambiguous (changing `|S_num|`); the contingency cap (1–3) couldn't express route (b) at the default conditioning bound; "minimizing" separating set was selection-order-dependent. Any future change to routes, caps, or knobs re-checks totality and determinism across all three axes, not just the axis being edited.
   - `internal/verifier/stats/stats.go`: pure-Go statistical primitives — regularized upper incomplete gamma (for the chi-square survival function), `ChiSquareP(stat, dof)`, G-statistic from a contingency table, partial correlation from a correlation matrix by matrix inversion over ≤4 variables (pair + conditioning set ≤2), Fisher-z test with the **conditioned** degrees of freedom — `z = sqrt(n − |S| − 3) · atanh(r)` where `|S|` is the conditioning-set size (the marginal `sqrt(n−3)` form is wrong for conditional tests) — two-sided normal p via `math.Erfc`, a stratified pooling rule (below), and Benjamini–Hochberg over a slice of p-values. The partial-correlation inversion carries a **degeneracy guard**: before inverting, check the correlation matrix's condition (a determinant/pivot floor, e.g. |det| < 1e-12, suffices at ≤4×4); a singular or near-singular conditioning matrix — near-collinear conditioners — maps the test's status to `unknown` (edge retained, fail-closed) instead of letting NaN/±Inf flow into Fisher-z and the BH pool. Table-driven unit tests against reference values (scipy-computed constants embedded in the test), including a collinear-conditioner case asserting the `unknown` routing.
   - **Conditional-test routing and pooling — the exact contract, exhaustive over endpoint and conditioner compositions.** Route selection is by **endpoint pair first**: **mixed endpoints (one categorical, one numeric) quantile-bin the numeric endpoint at `DiscoveryBins` and are then treated as categorical endpoints** — the same reduction level 0's binned hybrid uses, so every pair type has one route at every level. Conditioner handling is a fixed rule, never a choice: **categorical conditioners stratify (raw values in the group key); numeric conditioners are handled per route — partialled in route (a)/(c), quantile-binned into the group key only in route (b)**. The routes: (a) numeric endpoints + all-numeric conditioners → partial correlation via the moments cross-product sums, Fisher-z at `|S|` df; (b) categorical (or binned-mixed) endpoints, any conditioners → joint contingency grouped by all conditioners (categoricals raw, numerics binned), G-test within each conditioning stratum, summing G statistics and dof across strata (the standard conditional G-test); (c) numeric endpoints with ≥1 categorical conditioner → grouped `moments` with the group key = the **categorical conditioners only**, requesting cross-products over {X, Y, numeric conditioners}; per-stratum **partial** correlation partialling out the numeric conditioners, so `|S_num|` = the count of numeric conditioners, deterministically; pooled by **weighted Fisher-z**: `Z = Σᵢ (nᵢ − |S_num| − 3)·zᵢ / sqrt(Σᵢ (nᵢ − |S_num| − 3))` over strata with nᵢ ≥ 5 + |S_num| + 3, two-sided normal p. Strata below the minimum size are dropped from the pool; if all strata drop, the test's status is `unknown` (fail-closed, edge retained).
   - `internal/verifier/discovery.go`: the PC-style sweep.
     - **Column selection** (R4 acceptance): pull the column inventory via the `analyzer` seam's `Introspect`; if count > `DiscoveryColumnCap`, select deterministically — objective columns (from `goalReader`'s `EvaluationMatrix`) and finding-referenced columns (from the `graphWriter` seam's `ListEligibleFindings`-backed read, extracting the columns named in each finding's intervention filters) first, then descending pairwise association strength with the objective columns (measured with the level-0 tests), ties broken by column name; record excluded columns for persistence in Step 6.
     - **Level-0 sweep**: for every remaining pair, choose the test by column-type pair — categorical×categorical → G-test on a `contingency` response; numeric×numeric → correlation from a `moments` response; mixed → binned hybrid (`contingency` with the numeric side quantile-binned at `DiscoveryBins`). Apply BH FDR across each level's p-values at `DiscoveryAlpha`; independence ⇒ remove the edge.
     - **Conditional levels 1..MaxCondSet**: PC-style — for each surviving edge, test against conditioning sets drawn from current adjacencies (routing per the contract below). Remove on accepted independence; record the separating set (needed for collider orientation in Step 5).
     - **BH family at conditional levels** (level 0 is one test per pair — unambiguous): at each level ℓ ≥ 1, run **all** (edge, conditioning-set) tests of that level first, then apply BH once over that pooled family; an edge is removed if **any** of its tests is significant-for-independence after correction (equivalently: accepted-independent); the recorded separating set is chosen deterministically among the edge's accepted-independent sets: **maximum p-value first, ties broken by smallest cardinality, then lexicographic column order** (the choice feeds collider orientation, so it must be pinned, not incidental to loop order). Do not remove edges mid-level — removal happens between levels so the family composition and the adjacency structure used to draw conditioning sets are deterministic. This pins the skeleton against the regression thresholds; document the choice in `discovery.go`.
     - **Discovery budget guard**: the user-chosen default cap of 50 columns is ~1,225 pairs — at conditioning bound 2 the worst-case test count reaches tens of thousands of sandbox round-trips (the spec's cost framing assumed ≤20 columns), while the lock holder pins a Postgres pool connection throughout. Bound the sweep with `DiscoveryMaxTests` (config, default ~20,000): compute the level's test count before running it; if the budget would be exceeded, stop escalating levels, mark untested pairs' status `budget_capped` (retained unoriented — fail-closed, same disposition family as `unknown`), and record the truncation on `CausalGraphMeta` so verification can report it. Log the estimated test count at discovery start.
     - **Fail-closed** (R4 acceptance): a test that errors or times out marks the pair's status `unknown` — the edge is retained, flagged unoriented-unknown, never silently dropped or directed; the statuses persist to the graph so R10 (Shell 7) can report not-identifiable.
   - Every sandbox call goes through the `analyzer` seam with per-call timeouts; unit tests drive the sweep with a fake analyzer computing the aggregates in-process from parsed CSV rows.

5. **Deterministic orientation, then the batched LLM orientation call**
   - `internal/verifier/orient.go`: collider orientation (for each unshielded triple X–Z–Y, orient X→Z←Y when Z is not in the recorded separating set of (X,Y)), then Meek rules 1–4 to propagate. **Orientation eligibility is status-gated (R4 fail-closed): only `tested` edges may be directed.** Edges with `unknown`/`budget_capped` status participate in the skeleton for adjacency and unshielded-triple detection but are fixed-undirected — collider and Meek rules skip them as orientation targets (they may still inform a rule's premises as undirected adjacencies), and they reach the LLM stage excluded from the orientable batch. Without this gate, standard Meek propagation would silently direct a fail-closed edge and assign it `statistical` provenance — exactly what R4's acceptance forbids. Pure functions over the skeleton + separating sets + statuses; table-driven tests on hand-built graphs with known CPDAGs, including a case asserting an `unknown` edge stays undirected under a Meek rule that would otherwise fire.
   - `OrientCausalEdges` on `internal/llm/client.go`'s `Client` interface + `RepairOrientCausalEdges` sibling, implemented in the concrete client following the generate(+repair) pattern (`client.go:95-199`). Prompt: goal description and column semantics (names, types, sample values) wrapped in a fresh `NewFence("COLUMN-CONTEXT")`; the still-unoriented edge list enumerated with stable ids. Flat structured-output schema (per `schema.go`'s ceiling rules): array of `{edge_id: string, decision: enum("first_causes_second","second_causes_first","abstain"), confidence: number}` — no nesting, no growing enums.
   - Caller in `internal/verifier/orient.go`: one batched call for all edges Meek left unoriented; deterministic validation after decode (edge ids must exist and still be unoriented; anything else is a repair error); bounded repair loop (`OrientMaxRepairs`, pattern of `submit.go:248`); on exhaustion the batch's remaining edges stay unoriented (fail-closed, abstain-equivalent). Orient-or-abstain only — the response can never add or delete an edge (R5). LLM-oriented edges get provenance `llm_prior` and the model's confidence; statistically oriented edges get `statistical` and confidence 1.0.

6. **Persist the graph behind the advisory-lock single-flight; expose the read endpoint**
   - Domain additions in `internal/domain/domain.go`: `RelationCauses = "CAUSES"` relation constant; `EdgeProvenance` enum (`statistical`, `llm_prior`, `analyst` — R6; `analyst` is written by Shell 7's correction flow but belongs in the enum now); `DataColumn` and `CausalEdge` structs (edge: canonical column pair (colA < colB), `direction` (`a_to_b`/`b_to_a`/`undirected`/`unknown`), status (`tested`/`unknown`/`budget_capped` — the latter two fail-closed), provenance, confidence, version); a `CausalGraphMeta` struct (goal, datasource, version, excluded columns, budget-truncation record from Step 4's guard, discovery timestamp, tuning snapshot).
   - Graph writers in `internal/graph/neo4j.go` following the `CreateMetaHeuristic` (`:292`) MERGE shape. **Node identity follows the existing `id`-unique convention**: `InitSchema`'s labels loop emits only `REQUIRE n.id IS UNIQUE` constraints, which cannot enforce a composite key — so `DataColumn` and `CausalGraphMeta` nodes carry a **deterministic synthesized `id`** (UUIDv5/SHA-256 over the composite key: `goal_id \x00 datasource_ref \x00 name` for columns, `goal_id \x00 datasource_ref \x00 version` for meta) and MERGE on `{id}`; the composite parts are stored as ordinary properties for querying. This keeps the constraint meaningful, the writes idempotent, and the labels-slice addition honest. `UpsertDataColumns` (MERGE on the synthesized `id`), `UpsertCausalEdges` (MERGE `CAUSES` between the two column nodes' synthesized ids, relationship keyed on the **canonical undirected pair** — (goal_id, datasource_ref, version, colA, colB) with colA < colB lexicographically — and `direction` (`a_to_b`/`b_to_a`/`undirected`/`unknown`) stored as a **property** alongside provenance/confidence/status. Directed MERGE keys would orphan edges: MERGE never deletes, and a crashed run whose re-run orients the same pair the other way — LLM orientation is non-deterministic — would leave both directions "committed" under version 1. With the undirected key, re-orientation only updates properties. For the same reason, a re-discovery whose skeleton differs from a prior torn write must **delete all version-1 `CAUSES` edges and `DataColumn` orphans for the (goal, datasource) before writing its own edge set** — a version-scoped cleanup, safe because meta does not yet exist so nothing committed is lost), `UpsertCausalGraphMeta` + `GetCausalGraph(goalID, datasourceRef)` reading the newest **committed** version. Add `DataColumn` (and the meta label) to `InitSchema`'s `labels` slice in `internal/graph/schema.go:15`. Remember the Neo4j FOREACH gotcha: conditional property writes are standalone `FOREACH (_ IN CASE …)` clauses placed before any `UNWIND`.
   - **Version derivation + commit marker (R4 crash-idempotency).** An initial discovery always writes **version 1** — deterministic, so a crashed run's re-run MERGEs over the same (goal, datasource, 1) keys idempotently rather than allocating a new version and leaving two partial graphs. Version increments belong to Shell 7's analyst-correction/re-discovery path, not this shell. Write ordering is the commit protocol: columns and edges first, `CausalGraphMeta` **last** — the meta node is the commit marker. `GetCausalGraph` returns a graph only when its meta exists; a torn partial write (holder crashed mid-write; session death auto-released the advisory lock) therefore reads as absent → 404 on the endpoint → the next requester re-discovers over the same keys. Waiters' recheck loops poll for the *committed* meta, never raw edges.
   - Advisory lock in `internal/store` (new `advisorylock.go`): `TryAcquireDiscoveryLock(ctx, goalID, datasourceRef)` hashes the pair to an int64 key (fnv-1a over `goalID + "\x00" + datasourceRef`) and calls `pg_try_advisory_lock` on a **dedicated acquired connection** (`pool.Acquire`). **Release semantics (pgx v5):** session-level advisory locks bind to the physical backend connection, and `(*pgxpool.Conn).Release()` returns the connection to the pool **with the lock still held** — the lock would leak to the next borrower. The returned release func must therefore execute `SELECT pg_advisory_unlock($1)` on the same conn, verify it returned `true` (log loudly if not), and only then `Release()` the conn; on unlock failure, destroy the connection (`conn.Conn().Close(ctx)` path / `Hijack`) rather than pooling it. On a failed try-acquire, release the conn immediately — never hold a pooled connection while waiting. Document that this is the repo's first advisory-lock use, and that the holder pins one pool connection for the entire multi-round-trip discovery — pool sizing must account for concurrent per-goal discoveries.
   - **Waiter semantics (R4: concurrent requesters wait on the one result) — no blocking `pg_advisory_lock` waits.** N R3-fan-out waiters each parked in a blocking lock call would pin N pool connections for the full discovery (minutes), exhausting the pool. Instead: loop { `TryAcquire` → on success, re-check whether a committed graph now exists (another holder may have finished) and either return it or run discovery; on failure, release any conn, sleep with jittered backoff (e.g. 2–5s, context-deadline-aware) and re-check `GetCausalGraph` for a committed version, returning it the moment it appears }. Each attempt holds a connection only momentarily; context cancellation exits the loop cleanly.
   - Orchestrator read endpoint (R6): `GET /goals/{id}/causal-graph` in `internal/orchestrator/server.go` `Routes()`, unauthed like the other reads, handler modeled on `handleHeuristicTrace` (`internal/orchestrator/heuristics.go:91`) — resolve the goal's `datasource_ref` from `goal_registry`, fetch via the graph repo's `GetCausalGraph`, map to a DTO (nodes, edges with provenance/confidence/status, meta incl. excluded columns and version), 404 when no graph exists yet.
   - Audit events (`internal/orchestrator/audit.go` / `POST /internal/audit` contract): emit `causal_discovery_started` / `causal_discovery_complete` (with edge counts, test counts, unknown-pair count) from the verifier via the existing internal audit client path.

7. **Regression-test discovery against the planted graph**

   - Assert: skeleton precision and recall ≥ pinned thresholds (set from the first honest run, e.g. ≥0.8/≥0.8 — pin actual observed values, leaving slack for boundary noise); the confounder-induced spurious `X–Y` edge is removed at conditioning level 1; the true `A → Y` edge survives; determinism — two runs over the same rows produce identical graphs.
   - An `ARBORETTE_INTEGRATION`-gated variant drives the same dataset through the real sandbox `/analyze` (CGO, staged CSV) to catch compile/binding drift between the fake analyzer and real DuckDB SQL.
