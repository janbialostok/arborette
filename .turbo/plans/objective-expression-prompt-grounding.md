# Plan: Objective Value-Expression Prompt Grounding (depth-independent intake schema)

## Context

Registering a goal against a wide dataset (e.g. Spaceship Titanic `train.csv`) still fails with Anthropic's `400 invalid_request_error: "The compiled grammar is too large… Simplify your tool schemas or reduce the number of strict tools."`, which the orchestrator maps to a 502 "evaluation matrix generation failed". The prior fix (commit `b9f40b9`, plan `wide-dataset-column-grounding.md`, status done) removed the per-column `enum`s so the schemas became width-independent — but a **live E2E re-test proved that insufficient**: a narrow 4-column dataset fails identically, and a live schema-depth probe pinpointed the real ceiling as the **objective value-expression AST depth**, not column cardinality. Anthropic's structured-output grammar rejects recursive schemas outright, and the current bounded-depth workaround (`maxExprDepth = 3` in `internal/llm/schema.go`, a `$defs`/`$ref` DAG of per-kind `anyOf` variants) compiles to a grammar that exceeds the size ceiling at depth ≥ 2. So schema-aware intake has never actually worked against the real API for any objective that needs a compound value expression.

The pinned direction (confirmed in turboplan): **stop emitting the strict AST schema for the objective value expression.** Represent the `value` field as a plain `string` in the strict schema, whose content is a JSON-encoded `domain.Expression`; describe that AST shape in the prompt; and parse + validate the returned JSON deterministically through the **already-shipped** sandbox dry-run + bounded repair loop in `internal/orchestrator/submit.go`. This is the same philosophy the column fix used (ground via prompt, validate deterministically after generation) applied to the one remaining strict-AST site. A plain-`string` field has trivial, depth-independent grammar, so the compiled grammar no longer scales with expression structure or dataset width, and full expressiveness — including the depth-2 `CASE`-bucket shape `avg(CASE WHEN age > 18 THEN 1 ELSE 0 END)` — is preserved at zero grammar cost.

Design decisions resolved in turboplan:
- **Representation of `value`: a JSON-encoded `domain.Expression` string** (not an open object — Anthropic's structured outputs require `additionalProperties:false` on every object and reject `additionalProperties` set to anything else, and reject recursive schemas; not a bespoke DSL — a JSON string reuses `domain.Expression`'s existing `json.Unmarshal`/`renderExpr` with zero new parser).
- **A modest deterministic depth guard** on the parsed expression, enforced as a repairable failure through the existing dry-run + repair loop, since the strict schema no longer bounds nesting.
- Scope is the **objective value expression only.** `ProposeInterventionTree`/`RepairInterventionTree` emit filters (plain strings) with no expression AST, and `interventionTreeSchema` is already static — untouched.

Secondary benefit: `evaluationMatrixSchema()` becomes fully **static** (independent of `SandboxSchema` and of any depth constant), so it — like the intervention-tree schema — becomes eligible for Anthropic's 24-hour structured-output compile cache.

## Pattern Survey

### Analogous Features
- `internal/llm/schema.go:56-81` — `evaluationMatrixSchema` is the direct target. Its doc comment IS the `b9f40b9` precedent: column references and constraint fields were dropped from per-column enums to plain strings ("grounded to the real columns via the prompt and validated against the schema after generation"), leaving only fixed-cardinality enums (direction/aggregation/op). The `value` field (`:70`, `expressionRef(maxExprDepth, defs)`) is the one part still built as a strict AST — the thing to loosen.
- `internal/llm/schema.go:165-181` — `interventionTreeSchema` + `constraintItem` are the fully-realized `b9f40b9` pattern: filter `field` is a bare `stringProp()`, grounded via prompt, validated deterministically after generation. This is the exact "loosen schema → ground via prompt → validate deterministically" shape to apply to `value`.
- `internal/orchestrator/submit.go:82-103` — the dry-run + bounded-repair seam for the objective: `dryRunObjective` → `isObjectiveValidationFailure` → `RepairEvaluationMatrix`, looped up to `maxObjectiveRepairs` (=3). A repairable failure is a pin failure or sandbox 400; exhaustion → 422, sandbox fault → 502. **This loop already exists and is where the depth-guard failure slots in** — no new loop.
- `internal/orchestrator/hypothesis.go:295-333` — `proposeValidCandidates` / `splitByColumns` (the loop half of `b9f40b9`, using `domain.UnknownFilterColumns`). Prior art for "validate deterministically after loosening"; not modified by this change (filters carry no expression).
- `internal/domain/domain.go:282-313` — `UnknownFilterColumns`, the CGO-free deterministic grounding check for loosened filter strings. The new `ExpressionDepth` guard is its sibling: a dependency-free deterministic check on model output that feeds the repair loop.

### Reusable Utilities
- `internal/domain/domain.go:157-224` — `Expression` is a flat "fat node" discriminated union with stdlib json tags and NO custom (un)marshaler; `domain_test.go`'s `TestExpressionRoundTrip` confirms all six kinds (incl. nested `case`/`comparison`/`arithmetic`) survive plain `json.Marshal`/`json.Unmarshal`. So a returned JSON-string `value` parses into `domain.Expression` via a bare `json.Unmarshal` with zero extra parser. `renderExpr` (`:193-224`) renders the reverse for prompts/labels.
- `internal/domain/domain.go:123-128` — `Target.ValueExpression()` resolves the target's expression (explicit `Value`, else degenerate ColumnRef over legacy `Field`); consumed by `pinObjective` (`hypothesis.go:384`) and `dryRunObjective`. The decoded parse just needs to populate `Target.Value`.
- `internal/llm/client.go:62-100` — `GenerateEvaluationMatrix` / `RepairEvaluationMatrix`, both currently `json.Unmarshal([]byte(body), &matrix)` straight into `domain.EvaluationMatrix`. This is the single decode point that changes.
- `internal/llm/client.go:153-159` — `proposalWire`, the established pattern of a private wire struct when the structured body isn't identical to the domain type. The matrix decode gains an analogous `evaluationMatrixWire` (value as a JSON string, re-`Unmarshal`ed into `domain.Expression`).
- `internal/llm/client.go:166-191` — `complete(ctx, effort, schema, system, user)`, the single call path (`OutputConfig.Format = anthropic.JSONOutputFormatParam{Schema: schema}`). Unchanged.
- `internal/llm/schema.go:189-234` — schema combinators (`object`, `arrayOf`, `stringProp`, `enumSchema`, `directionEnum`, `aggregationEnum`, `constraintOpEnum`, `toAny`). `stringProp()` is the loosened `value`'s new schema.

### Convention Anchors
- **Structured-output object convention is strict and uniform** (`schema.go:189-196`, `object()` unconditionally sets `additionalProperties:false` + `required`; `schema_test.go` asserts it). There is NO open-object precedent in the repo, and the `claude-api` skill's structured-output limitations confirm the API rejects open objects and recursive schemas — so a plain `string` is the only viable depth-independent representation.
- **Anthropic SDK fake** (`client_test.go`): `message(t, stop, blocks...)` JSON-round-trips a body string into `*anthropic.Message` so `AsText` reads from `.raw`; `textBlockJSON`/`thinkingBlockJSON` wrap block content. New/updated llm tests must build canned bodies this way (struct literals don't populate `.raw`).
- **Orchestrator test doubles** (`server_test.go`): `fakeClaude` (records `gotSchema`, scripts `matrix`/`repair`, counts `repairCalls`); `fakeSandbox` (per-call `execResps`/`execErrs` indexed by `execCalls`). `submit_test.go` scripts `domain.EvaluationMatrix` values directly (no schema), so those tests are unaffected by dropping the strict AST schema — the new depth-guard case is added here.
- **Error sentinels + `isObjectiveValidationFailure`** (`hypothesis.go:22-23,420-430`): `errNoObjective`/`errMissingAggregation` are `errors.New` sentinels classified as repairable alongside a sandbox 400. The depth-guard failure is a new sibling sentinel classified the same way.
- **CGO boundary is load-bearing** (`sandboxclient.go:19-25`): the orchestrator/llm/domain packages are CGO-free and must not import `internal/sandbox`. The dependency-free `internal/domain` (already imports only `strings`/`strconv`) is the idiomatic home for `ExpressionDepth` — Go 1.24, so the `max` builtin is available.

### Proposed Alignment
Apply the realized `b9f40b9` filter-field pattern to the objective `value`: replace the strict AST (`expressionRef`/`expressionDef`/`maxExprDepth`/`literalSchema`/`constProp`, `schema.go:50-157,208-212`) with `stringProp()`; decode the returned JSON-string into the flat `domain.Expression` fat node via a `proposalWire`-style `evaluationMatrixWire`; ground the AST shape in the strengthened `evaluationMatrixSystem`/`evaluationMatrixRepairSystem` prompts; add one CGO-free `domain.ExpressionDepth` guard; and route both a too-deep expression through the **existing** `dryRunObjective` → `RepairEvaluationMatrix` loop. A malformed `value` string (rare with a clear prompt) stays a generation error → 502, matching today's `json.Unmarshal` failure handling. No new loop, no new validation seam, no CGO import.

## Implementation Steps

1. **Loosen the objective `value` to a plain string in the matrix schema** (`internal/llm/schema.go`)
   - In `evaluationMatrixSchema` (`:68-81`): replace `value := expressionRef(maxExprDepth, defs)` and the `root["$defs"] = defs` wiring with `"value": stringProp()` inline; drop the `defs` map and the `$defs` assignment. Keep `direction`/`aggregation` enums and `constraints`/`constraintItem` exactly as-is. The `_ SandboxSchema` arg stays (unused, symmetric with the caller).
   - Delete the now-dead strict-AST machinery: `maxExprDepth` (`:50-54`), `expressionRef` (`:83-94`), `expressionDef` (`:96-146`), `literalSchema` (`:148-157`), and `constProp` (`:208-212`, used only by `expressionDef`). Remove the now-unused `strconv` import (`:3-5`) — this is a compile error if left. `domain` stays imported (used by the enums).
   - Net effect: `evaluationMatrixSchema()` is fully static (no `SandboxSchema`, no depth constant, no `$defs`) → compiled grammar is depth- and width-independent, and the schema becomes compile-cacheable like `interventionTreeSchema()`.

2. **Decode the JSON-string `value` into `domain.Expression` in the Claude client** (`internal/llm/client.go`)
   - Add a private `evaluationMatrixWire` struct (mirror `proposalWire`'s convention): `Targets []struct{ Direction domain.TargetDirection `json:"direction"`; Aggregation string `json:"aggregation"`; Value string `json:"value"` }` and `Constraints []domain.Constraint `json:"constraints"``.
   - Add `func decodeMatrix(body string) (domain.EvaluationMatrix, error)`: `json.Unmarshal` the body into `evaluationMatrixWire`; for each target `json.Unmarshal([]byte(t.Value), &expr)` into a `domain.Expression`, wrapping a failure as `fmt.Errorf("parse target %d value expression: %w", i, err)`; assemble `domain.Target{Direction, Aggregation, Value: &expr}` and the `domain.EvaluationMatrix{Targets, Constraints}`. A malformed inner string returns an error (→ 502, matching today's top-level parse-failure handling).
   - Replace the `json.Unmarshal([]byte(body), &matrix)` blocks in `GenerateEvaluationMatrix` (`:69-72`) and `RepairEvaluationMatrix` (`:95-98`) with `matrix, err := decodeMatrix(body)`.
   - In `RepairEvaluationMatrix` (`:82-89`), the prior matrix is marshaled into the repair prompt to show the model what failed. Re-encode it through the wire (each `t.ValueExpression()` `json.Marshal`ed back to a string) via a small `func encodeMatrixWire(domain.EvaluationMatrix) (evaluationMatrixWire, error)` helper, so the prior shown to the model matches the JSON-string-`value` shape the output schema now demands (not a bare object).

3. **Ground the AST shape in the matrix system prompts** (`internal/llm/client.go`)
   - Add an `expressionShapeGuide` string constant describing the `domain.Expression` JSON shape the `value` field must contain (a JSON object encoded as a string): the `kind` discriminator and the six kinds — `column_ref {column}`, `literal {literal:{number|string|bool}}`, `cast {operand, cast_type}`, `comparison {op, left, right}`, `arithmetic {op, left, right}`, `case {cases:[{when,then}], else}` — with the boolean-rate example (`avg` over `comparison Transported = True`) and the CASE-bucket example. State that `value` MUST be emitted as a JSON string, referencing only columns from the "Available columns" list.
   - Append `expressionShapeGuide` to `evaluationMatrixSystem` (`:204-211`) and `evaluationMatrixRepairSystem` (`:213-218`). Leave `columnSummary` in the user message as the source of the column list. Do NOT touch `interventionTreeSystem`/`interventionTreeRepairSystem` (no expression there).

4. **Add a CGO-free expression depth guard** (`internal/domain/domain.go`)
   - Add `const MaxObjectiveExpressionDepth = 6` and `func ExpressionDepth(e Expression) int` walking the fat node (leaf kinds → 1; `cast` → `1 + child(Operand)`; `comparison`/`arithmetic` → `1 + max(child(Left), child(Right))`; `case` → `1 + max` over each branch `When`/`Then` and `Else`), with a nil-safe `childDepth(*Expression) int` (nil → 0). Use the Go 1.24 `max` builtin. Home it next to `renderExpr` (`:193-224`); `domain` gains no new imports. (Real objectives are shallow, so 6 is generous headroom while still rejecting pathological trees; document the cap's rationale in the doc comment. **Terminology:** the "depth-2 CASE-bucketing" phrasing in Context/Verification is the old composite-`$ref`-level metric inherited from the improvements note — under this new `ExpressionDepth` metric, which counts a leaf as 1, that same `avg(CASE WHEN age > 18 THEN 1 ELSE 0 END)` shape is `case`(depth 3) over a `comparison`(depth 2) over a `column_ref`(depth 1). The two numbers describe the identical shape; the cap of 6 admits it with ample margin.)

5. **Enforce the depth guard as a repairable failure in the registration dry-run** (`internal/orchestrator/hypothesis.go`)
   - Add a sentinel `errExpressionTooDeep = errors.New(...)` alongside `errNoObjective`/`errMissingAggregation` (`:22-23`).
   - In `dryRunObjective` (`:411-418`), after `pinObjective` and before the sandbox `Execute`, if `domain.ExpressionDepth(obj.expr) > domain.MaxObjectiveExpressionDepth`, return `fmt.Errorf("%w: objective value expression nests too deeply (max %d)", errExpressionTooDeep, domain.MaxObjectiveExpressionDepth)`. Keeping the check here means the message flows verbatim into `RepairEvaluationMatrix(...)` via the existing loop.
   - In `isObjectiveValidationFailure` (`:424-430`), add `errors.Is(err, errExpressionTooDeep)` to the repairable branch. `submit.go`'s loop (`:85-99`) is unchanged: it now also repairs a too-deep objective, exhausts to 422, and never mislabels it a sandbox fault.

6. **Update and add tests** (see Verification for the full matrix)
   - `internal/llm/schema_test.go` — rewrite the `value` section of `TestEvaluationMatrixSchema` (`:90-168`): assert `tprops["value"]` is a plain string schema (`type == "string"`, no `enum`, no `anyOf`, no `$ref`) and that `s["$defs"]` is absent; keep the `direction`/`aggregation`/`additionalProperties`/`no field` assertions. Delete the `$defs`/`resolveRef`/`anyOfVariants` depth-walk block and the `for depth := maxExprDepth` loop (`:158-167`). Deleting that block removes the only caller of the `resolveRef` helper (`:72-88`) — remove `resolveRef` too, and drop the now-orphaned `"strings"` import (`:6`, `resolveRef`'s sole consumer) to avoid an unused-import compile error. `TestSchemaWidthIndependent` and `TestInterventionTreeSchema` pass unchanged.
   - `internal/llm/client_test.go` — update `TestGenerateEvaluationMatrix` (`:56-89`) and `TestGenerateEvaluationMatrixSkipsLeadingThinkingBlock` (`:91-`): the canned `value` in every matrix body must now be a JSON *string* containing the expression (e.g. `"value":"{\"kind\":\"comparison\",...}"`), not an object; assertions on the round-tripped `ComparisonKind`/`ColumnRefKind` expression stay. **Rewrite the existing `TestRepairEvaluationMatrix` (`:109-132`) — do not add a second one** (its current canned body has `"value":{"kind":"column_ref",...}` as an object, which now fails `decodeMatrix`'s string unmarshal): change its `value` to a JSON string, and update the prior-embedding assertion (`strings.Contains(user, `"aggregation":"avg"`)` at `:127`) to match the `encodeMatrixWire`-encoded prior shape — the field-only prior degenerates via `ValueExpression()` to a `column_ref`, `value` is re-encoded as a JSON string, and `aggregation` stays present, so assert on the wire-encoded prior text (e.g. the JSON-string `value` and the `"aggregation":"avg"` field), not the pre-change `json.Marshal(prior)` output. Add: (a) a malformed-`value`-string body → `GenerateEvaluationMatrix` returns an error (the 502 path).
   - `internal/domain/domain_test.go` — unit-test `ExpressionDepth`: leaf = 1, the boolean-rate comparison indicator, the depth-3 CASE-bucket, and a hand-built over-cap tree; nil-child safety.
   - `internal/orchestrator/submit_test.go` — add a case: `GenerateEvaluationMatrix` returns a matrix whose objective expression exceeds `MaxObjectiveExpressionDepth`; assert the dry-run classifies it repairable, `RepairEvaluationMatrix` is called (bounded), a subsequent within-cap matrix persists 201, and an always-too-deep matrix exhausts to 422. Confirm `TestSubmitGoalRepairsExhaustedIsUnprocessable`, `TestSubmitGoalDryRunRepairThenSuccess`, and `TestSubmitGoalRepairErrorIsBadGateway` still pass unchanged.
