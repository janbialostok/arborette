# Plan: Objective Expression Contract & Sandbox Compilation

## Context

Today an objective is a bare `{field, direction}` bound to a single real column, and the sandbox measures `aggregation(field)` — which hard-fails on boolean/categorical fields ("numeric aggregation over non-numeric column"). To let analysts optimize things like "the rate of transported passengers", the objective's measured value must become a **structured expression** (columns, casts, comparisons, arithmetic, `CASE`/bucketing), and the sandbox must compile that expression to DuckDB SQL safely. This plan lays the executable foundation: the expression AST, the additive matrix/`Target` contract extension, the end-to-end **objective label** (so an expression with no single column name can still be requested, returned, and read back), and the sandbox's expression-compilation execute path. It is the contract everything else in this iteration builds on, so it must stay additive — legacy `{field, direction}` matrices deserialize unchanged and downstream shells (04/07/08 of the parent project) that read the matrix/`Outcome` are not forced to change.

**Decisions locked at expansion (were open questions):**

- **Objective label** — a **human-readable** key derived deterministically from the fitted objective: `domain.RenderObjectiveLabel(agg, expr)` renders e.g. `avg(Transported = True)`. It is carried on the execute request and echoed as the key of `ExecuteResponse.Value`. This plan delivers the renderer and the request/response fields; the orchestrator caller that populates them from a real fitted expression is the next shell's `pinObjective` rewrite (kept as a stable seam here).
- **Type rules** — the compiler does **coarse type-tracking** (numeric / boolean / string / temporal), decides casts from it (BOOLEAN→`INTEGER`, `Comparison`→`0/1` indicator), and rejects clearly-invalid combinations (arithmetic over a string, `avg` over a non-castable string result, a `Cast` from string/temporal data to a numeric type) up front with a descriptive `{error}`. Every top-level expression compiles to a `DOUBLE`-yielding aggregate. The **invariant** is that no supported expression reaches the client as a masked `500` or an unencodable `200` body (R6's deterministic validation + R7's clear failures), and it holds **structurally**, not by enumerating error strings:
  - Compile-time type-validity rejects the type-level failures (unknown/ambiguous column, mismatched `Comparison`/`Arithmetic` operands, string/temporal→numeric `Cast`).
  - Value-level failures the type system cannot see are routed to one **post-scan non-finite guard** (`math.IsInf`/`math.IsNaN` → `400`): `Arithmetic` is compiled in floating-point space so an integer overflow becomes a guard-catchable `+Inf` rather than a mid-`Scan` DuckDB error, and the guard is unconditional so source-data `inf` on the legacy path is caught too.
  - The one remaining mid-`Scan` DuckDB error class (out-of-range numeric→`INTEGER` narrowing cast) is removed by **construction**: `INTEGER` is not a user-specifiable `Cast` target, so the objective's only integer cast is the compiler-emitted boolean→`INTEGER` (`0`/`1`, cannot overflow).

**Scope boundary:** this plan does **not** rewrite `pinObjective`, `numericValue`, the matrix-generation LLM schema, or the orchestrator's `Execute` caller in `hypothesis.go`. Those are the next shell. Here the legacy field-keyed path stays wired and green; the new expression path is additive and exercised only through direct sandbox/domain tests until shell 02 populates it.

## Pattern Survey

### Analogous Features

- `internal/sandbox/compile.go:71` — `compileQuery` is the existing deterministic AST-free compiler the new expression path parallels: allowlist-maps the aggregation (`allowedAgg`), resolves each field against the introspected schema, guards numeric-only aggregations via `isNumeric`, quotes only schema-present column names, binds threshold values as `?`. The Step 4 expression compiler is a direct extension of this function's structure.
- `internal/sandbox/compile.go:26,36` — `allowedAgg` / `allowedOp` maps are the "operator/function never reaches SQL uninterpreted" pattern the `Comparison`/`Arithmetic` AST nodes reuse for their operators.
- `internal/sandbox/compile.go:133` — `resolveColumn` (0/1/many → unknown/ok/ambiguous) is the exact per-`ColumnRef` validation the AST compiler needs; `matchColumns` (`compile.go:119`) is the shared case-insensitive rule.
- `internal/sandbox/compile.go:147` — `isNumeric` keys off the DuckDB type string (uppercased, DECIMAL by prefix). BOOLEAN→INTEGER / categorical→indicator type checks hang off this.
- `internal/sandbox/server.go:176` — `writeStageErr` is the sentinel→HTTP-status mapping: each compiler sentinel is `errors.Is`-matched to 400, everything else masked to 500. New expression sentinels must be added here to surface as descriptive `{error}` bodies (Step 5).
- `internal/store/goalregistry.go:33,60` — `EvaluationMatrix` is `json.Marshal`/`json.Unmarshal`ed as jsonb into `goal_registry.evaluation_matrix`; `store_test.go:218` shows a legacy `'{}'` matrix persisting. This is the round-trip the additive `Target`/expression fields must survive.
- `internal/sandbox/server.go:74-87` ↔ `internal/orchestrator/sandboxclient.go:60-71` — `ExecuteRequest`/`ExecuteResponse` defined twice, byte-for-byte. Both copies gain the new fields (Step 3).

### Reusable Utilities

- `internal/sandbox/compile.go:156` — `quoteIdent` — double-quotes a validated identifier; the AST `ColumnRef` emitter reuses it verbatim.
- `internal/sandbox/filesource.go:237` — `escapeLiteral` — doubles single quotes for a SQL literal; a fallback if a literal cannot be bound as `?`. Prefer binding literals as `?` args (see Step 4 arg-ordering note); `escapeLiteral` is the escape hatch only where a bound placeholder cannot be typed.
- `internal/domain/domain.go:129,132` — `Aggregations` + `IsAggregation` — canonical aggregation set, single-sourced into the LLM schema enum. Note the sandbox keeps its **own** `allowedAgg` map (`compile.go:26`), so two aggregation lists already exist; the new expression path validates the request aggregation against `allowedAgg` exactly as `compileQuery` does — do not add a third list.
- `internal/orchestrator/hypothesis.go:308` — `numericValue(value map[string]any, field string)` reads the value map by key, tolerating `float64` and `json.Number`. Unchanged in this plan; the next shell passes the objective label instead of `obj.field` here.
- `internal/sandbox/filesource.go:200-220` — `columns()` runs `DESCRIBE` and stores the raw `column_type` string (`BOOLEAN`, `VARCHAR`, `DECIMAL(10,2)`, `DATE`) into `datasource.Column{Name,Type}`. Casts key off these strings.

### Convention Anchors

- **No discriminated-union JSON marshaling exists anywhere.** A grep for `MarshalJSON`/`UnmarshalJSON`/`json.RawMessage` across `internal/` returns nothing; the only "discriminators" (`domain.InterventionType`, `datasource.SourceKind`) are string constants switched on in Go, never polymorphic decode. The AST's tagged-union representation is a brand-new pattern; this plan defines it explicitly (a flat "fat node" struct with a `Kind` field + `omitempty` subfields, so **stdlib decode suffices — no custom `Expression.UnmarshalJSON`**).
- **Additive/legacy-tolerant deserialization relies on stdlib default behavior.** `json.Unmarshal` silently ignores missing fields (legacy `{field,direction}` rows). There are no `omitempty` tags or optional pointer fields in `internal/domain` today. The "legacy row → degenerate ColumnRef" requirement is met with an **accessor** (`Target.ValueExpression()`), not a custom `UnmarshalJSON`, so a legacy row round-trips back **identically** (custom unmarshal would rewrite it, breaking R5's round-trip criterion).
- `internal/datasource/datasource.go:1-8` states the codebase's explicit additive-extension rule ("new methods go on a companion interface rather than changing this contract"). The `Target`/matrix extension follows this.
- **Wire-DTO duplication is a documented, deliberate coupling** (`sandboxclient.go:19-25`): the orchestrator must not import `internal/sandbox` (it blank-imports the CGO DuckDB driver; the orchestrator builds `CGO_ENABLED=0` distroless-static). Any execute-contract field is mirrored in both files; types come from dependency-free `internal/domain`.
- **Table-driven sandbox compiler tests:** `internal/sandbox/compile_test.go` uses a `testCols()` fixture (`compile_test.go:16` — DOUBLE/BIGINT/DECIMAL/VARCHAR/DATE, **no BOOLEAN yet**) with `cases []struct{...}` sub-tests asserting on rejection sentinels (`errors.Is`), quoted identifiers, `CAST(... AS DOUBLE)`, and bound-arg placement. New AST tests follow this shape and add a BOOLEAN column to the fixture.
- **No `internal/domain` test file exists.** The AST (un)marshal round-trip + label-render tests are the first domain-package tests; the nearest round-trip convention is `internal/llm/client_test.go` (canned-JSON via `json.Unmarshal`).
- **Value-map keying:** `ExecuteResponse.Value` is built as `map[string]any{req.Target.Field: measured}` (`server.go:142`); `Outcome.Value` keyed the same at `hypothesis.go:193`. The objective label becomes the new key at the sandbox emit site, with `Target.Field` retained as the fallback key when no label is supplied.

### Proposed Alignment

Reuse the `compile.go` machinery wholesale — `quoteIdent`, `resolveColumn`/`matchColumns`, the allowlist-map + sentinel-error + `writeStageErr` pattern, and `isNumeric` (extended so BOOLEAN maps to the coarse boolean type for the →INTEGER cast) — and mirror the `compile_test.go` table-driven style. The one genuinely new pattern is the AST's discriminated-union JSON: a flat `Kind`-tagged struct with `omitempty` subfields, decoded by stdlib, plus a `Target.ValueExpression()` accessor for the degenerate-`ColumnRef` legacy case. Every execute-contract change is applied to **both** DTO copies (`server.go` + `sandboxclient.go`) per the CGO coupling.

## Implementation Steps

1. **Define the expression AST in `internal/domain/domain.go`.**
   - Add `type ExpressionKind string` with constants `ColumnRefKind`, `LiteralKind`, `CastKind`, `ComparisonKind`, `ArithmeticKind`, `CaseKind`.
   - Add a flat "fat node" `type Expression struct` with a `Kind ExpressionKind json:"kind"` discriminator plus `omitempty` subfields covering every node:
     - `ColumnRef`: `Column string json:"column,omitempty"`.
     - `Literal`: `Literal *LiteralValue json:"literal,omitempty"` (a small struct carrying a typed scalar — number, string, or bool — so the compiler knows the literal's coarse type without inference).
     - `Cast`: `Operand *Expression json:"operand,omitempty"`, `CastType string json:"cast_type,omitempty"`.
     - `Comparison` / `Arithmetic`: `Op string json:"op,omitempty"`, `Left *Expression json:"left,omitempty"`, `Right *Expression json:"right,omitempty"`.
     - `Case`/bucket: `Cases []CaseBranch json:"cases,omitempty"` (each branch `{ When *Expression; Then *Expression }`) and `Else *Expression json:"else,omitempty"`.
   - Rely on stdlib (un)marshaling — no custom `MarshalJSON`/`UnmarshalJSON` on `Expression`. Document the discriminator convention in a doc comment (mirror the density of the existing `internal/domain` comments).
2. **Extend the `Target`/matrix contract additively in `internal/domain/domain.go`.**
   - Add to `Target` (currently `domain.go:103`): `Aggregation string json:"aggregation,omitempty"` and `Value *Expression json:"value,omitempty"`, retaining `Field`/`Direction`.
   - Add accessor `func (t Target) ValueExpression() Expression`: returns `*t.Value` when set, else the degenerate `Expression{Kind: ColumnRefKind, Column: t.Field}`. This is the single place the "legacy field-only row → degenerate ColumnRef" rule lives; no custom `UnmarshalJSON`, so legacy rows round-trip identically (R5).
   - `EvaluationMatrix` (`domain.go:89`) needs no field change — the new keys live inside each `Target`.
3. **Add the deterministic objective-label renderer in `internal/domain/domain.go`.**
   - `func RenderObjectiveLabel(agg string, expr Expression) string` → `agg + "(" + renderExpr(expr) + ")"`, with `renderExpr` recursing: `ColumnRef`→column name, `Literal`→its scalar, `Comparison`→`left op right`, `Arithmetic`→`left op right`, `Cast`→`operand::type`, `Case`→a compact `CASE …` form. Deterministic and dependency-free so both orchestrator (`CGO_ENABLED=0`) and sandbox import it. Delivered here; the orchestrator populates the request field with it in shell 02.
4. **Introduce the objective label + value expression on the execute contract (both DTO copies).**
   - In `internal/sandbox/server.go` `ExecuteRequest` (`server.go:74`) and the byte-for-byte copy in `internal/orchestrator/sandboxclient.go` `ExecuteRequest` (`sandboxclient.go:60`), add `ValueExpression *domain.Expression json:"value_expression,omitempty"` and `ObjectiveLabel string json:"objective_label,omitempty"`. Keep the existing `Aggregation`, `Target`, `Filters` fields.
   - In `internal/sandbox/server.go` `handleExecute` (`server.go:115`): compute the response key as `key := req.ObjectiveLabel; if key == "" { key = req.Target.Field }`, and build `ExecuteResponse{Value: map[string]any{key: measured}}`. Pass `req.ValueExpression` into the Execute call.
   - `ExecuteResponse` shape is unchanged (`map[string]any`), so `numericValue` and every downstream `Outcome` reader keep working; the next shell passes the label as the read key.
5. **Compile the AST to DuckDB SQL in `internal/sandbox/compile.go`.**
   - Add `type coarseType int` (values `typeNumeric`, `typeBoolean`, `typeString`, `typeTemporal`) and a `columnCoarseType(t string) coarseType` helper reusing `isNumeric` (numeric), plus BOOLEAN→boolean, VARCHAR/CHAR/TEXT→string, DATE/TIME/TIMESTAMP→temporal.
   - Add `func compileExpr(cols []datasource.Column, e domain.Expression) (sql string, typ coarseType, args []any, err error)`, recursive:
     - `ColumnRef`: `resolveColumn` (reuses unknown/ambiguous sentinels), emit `quoteIdent(col.Name)`, type from `columnCoarseType(col.Type)`.
     - `Literal`: emit `?` and append the typed scalar to `args`; type from the literal's declared kind.
     - `Cast`: compile operand, validate `CastType` against the **user-facing** `allowedCast` allowlist `{DOUBLE, VARCHAR, BOOLEAN}` — note `INTEGER` is **not** a user-specifiable cast target: a numeric→`INTEGER` narrowing cast of an out-of-range value (e.g. `CAST(1e20 AS INTEGER)`) raises a DuckDB conversion error mid-`Scan` that `writeStageErr` masks to a `500`, so the objective's only integer cast is the compiler-emitted boolean→`INTEGER` at the aggregate boundary (a `0`/`1` value that cannot overflow). Then **constrain the operand's coarse type** so the cast cannot fail at row-scan on dirty data: allow numeric→`DOUBLE`, boolean→`DOUBLE`, and anything→`VARCHAR`; **reject string/temporal→numeric and string→boolean at compile time** with `errTypeIncompatible` (a `CAST("<VARCHAR col>" AS DOUBLE)` over a non-numeric row otherwise raises a DuckDB conversion error at `QueryRowContext` masked to a `500`). Emit `CAST(<operand> AS <type>)`, type from the cast target.
     - `Comparison`: validate `Op` against a **new comparison-op allowlist** — a dedicated `map[string]string` keyed by the raw SQL-symbol operators the AST carries (`=`, `!=`, `<`, `<=`, `>`, `>=`). Do **not** reuse `allowedOp` (`compile.go:36`): that map is keyed by `domain.ConstraintOp` constants (`lt`/`lte`/`gt`/`gte`) for the filter path and cannot hold the AST's symbol operators. Compile both sides; **reject cross-operand type mismatches up front** — the two operands must share a coarse type (numeric↔numeric, string↔string, temporal↔temporal, boolean↔boolean; a `Literal` is comparable to a column of matching coarse type), else `errTypeIncompatible`. This keeps the deterministic-`400` guarantee: a numeric column compared to a string literal is caught here rather than reaching `QueryRowContext` and masking to a `500`. Emit `CASE WHEN (<left> <op> <right>) THEN 1 ELSE 0 END` → `typeNumeric` (the categorical `col = value` → indicator of R4).
     - `Arithmetic`: `Op` in `{+,-,*,/}`; **both operands must be `typeNumeric`** else `errTypeIncompatible`. **Compile in floating-point space** — wrap each operand as `CAST(<operand> AS DOUBLE)` before emitting `(<left> <op> <right>)` — so an integer (BIGINT) overflow, which DuckDB otherwise raises as an `Out of Range` error mid-`Scan` (masked to `500`), instead yields `+Inf` that the post-scan non-finite guard catches as a `400`. Result `typeNumeric`.
     - `Case`: each `When` compiles to a boolean-ish predicate, each `Then`/`Else` must be `typeNumeric`; emit `CASE WHEN … THEN … [ELSE …] END` → `typeNumeric`.
   - Add `func compileObjective(tableFn string, cols []datasource.Column, agg string, expr domain.Expression, filters []domain.Constraint) (string, []any, error)`: allowlist the aggregation via `allowedAgg` (as `compileQuery` does); compile the expression; **at the aggregate boundary** apply the coarse-type rule — numeric operand used as-is, `typeBoolean` wrapped as `CAST(<expr> AS INTEGER)` (the R4 boolean→`0/1` rule), `typeString`/`typeTemporal` rejected with `errTypeIncompatible` (except `COUNT`, which accepts any). Emit `SELECT CAST(<AGG>(<expr>) AS DOUBLE) FROM <tableFn>` + the existing filter `WHERE` clause. **Arg ordering:** expression args are appended before filter args because they appear earlier in the SQL text and `QueryRowContext` binds positionally — assert this ordering in a test.
   - Filters keep compiling exactly as today (numeric column comparisons, bound `?`); no change to the filter path.
6. **Branch the sandbox Execute path and surface descriptive errors.**
   - Extend `FileSource.Execute` (`internal/sandbox/filesource.go:86`) to accept the value expression, e.g. `Execute(ctx, agg string, target domain.Target, expr *domain.Expression, filters []domain.Constraint)`: when `expr != nil`, call `compileObjective`; else call the existing `compileQuery` (unchanged legacy path). **After `Scan` into the `sql.NullFloat64` (`filesource.go:103-110`) — at the shared scan site, on BOTH branches — guard the scanned value:** if `value.Valid && (math.IsInf(value.Float64, 0) || math.IsNaN(value.Float64))`, return `errNonFiniteValue`. A non-finite `DOUBLE` scans as a valid float64 but `json.Marshal` cannot encode it, and because `writeJSON` (`server.go:200`) has already called `WriteHeader(200)`, an unguarded value would emit a truncated `200` body the orchestrator surfaces as an opaque decode error. Two sources reach this: expression division by zero over the filtered subset (`+Inf`/`NaN`), and — on the **legacy path too** — `avg`/`sum`/`max` over a source `DOUBLE` column that contains `inf`. The guard is therefore unconditional (not gated on `expr != nil`); it converts either value-level failure into a descriptive `400`. The signature change touches **five** call sites, all of which must be updated (the plan's Verification `go test ./internal/sandbox/...` will not compile until they are): the production caller `internal/sandbox/server.go:132` (pass `req.ValueExpression`), and the four test callers `internal/sandbox/filesource_test.go:109,119,126,223` (pass `nil` for `expr` — they exercise the legacy path). `FileSource.Execute` is not part of the `datasource.DataSource` interface (which declares only `Kind()`/`Introspect()`), so the signature change does not ripple beyond these call sites.
   - Define new sentinels in `compile.go` alongside the existing block (`compile.go:15`): `errTypeIncompatible`, `errNonFiniteValue` (the division/`Inf`/`NaN` guard above), and `errUnknownCast` if the cast allowlist rejection needs its own message (a comparison-op rejection can reuse `errUnknownOperator`). Add each to the `errors.Is` switch in `writeStageErr` (`server.go:176`) so they return `400` with a descriptive `{error}` body. Unknown/ambiguous columns already flow through `errUnknownField`/`errAmbiguousField`.

## Verification

- `go build ./...` — both the sandbox (CGO) and orchestrator (`CGO_ENABLED=0`) still build; the shared `domain.Expression`/`RenderObjectiveLabel` are import-clean from the orchestrator.
- `go test ./internal/domain/...` (new `internal/domain/domain_test.go`):
  - `Expression` marshals and unmarshals round-trip for each node kind (ColumnRef, Literal, Cast, Comparison, Arithmetic, Case).
  - A legacy `Target` decoded from `{"field":"revenue","direction":"maximize"}` (no `aggregation`/`value`) yields `ValueExpression()` == degenerate `ColumnRef{Column:"revenue"}`, and re-marshals **byte-identically** to the legacy JSON (no `aggregation`/`value` keys emitted — the `omitempty` + accessor guarantee).
  - A `Target` carrying `aggregation:"avg"` + a `Comparison` value round-trips.
  - `RenderObjectiveLabel("avg", <Comparison Transported = True>)` == `"avg(Transported = True)"`.
- `go test ./internal/sandbox/...` (extend `compile_test.go`; add a BOOLEAN column to `testCols()`):
  - `avg` over a bare BOOLEAN `ColumnRef` compiles to `SELECT CAST(AVG(CAST("<col>" AS INTEGER)) AS DOUBLE) FROM …`.
  - A `Comparison` `col = 'x'` compiles to a `CASE WHEN ("<col>" = ?) THEN 1 ELSE 0 END` indicator with `'x'` bound as an arg (assert arg order: expression args before any filter args).
  - `Arithmetic` over a VARCHAR operand → `errTypeIncompatible`; a `Comparison` between a numeric column and a string `Literal` (mismatched coarse types) → `errTypeIncompatible` (caught at compile time, not leaked to `QueryRowContext`); a `Cast` of a VARCHAR column to `DOUBLE` → `errTypeIncompatible` (string→numeric rejected at compile time); a `Cast` with `cast_type: "INTEGER"` → `errUnknownCast` (`INTEGER` is not a user-facing cast target); unknown column in a `ColumnRef` → `errUnknownField`; `avg` over a bare VARCHAR `ColumnRef` (string coarse type at the aggregate boundary) → `errTypeIncompatible`.
  - `Arithmetic` emits `DOUBLE`-cast operands — assert the compiled SQL wraps each operand in `CAST(... AS DOUBLE)` so integer overflow routes to the guard rather than a mid-`Scan` error.
  - **Non-finite runtime guard (both branches):** an `Arithmetic` division whose divisor is zero over the filtered rows (e.g. `sum(a) / sum(b)` with `b` filtered to all-zero) returns `errNonFiniteValue` → `400 {error}`; and a **legacy** `avg`/`sum`/`max` (`expr == nil`) over a source `DOUBLE` column containing `inf` returns `errNonFiniteValue` → `400`. Both assert the value never reaches `json.Marshal`.
  - **Test call-site update:** the four `filesource_test.go` `Execute` calls (`:109,119,126,223`) pass `nil` for the new `expr` argument so the sandbox test build compiles.
  - **Legacy regression:** an Execute with `expr == nil` still compiles via `compileQuery` to the pre-existing `SELECT CAST(AVG("<col>") AS DOUBLE) …` and existing `compile_test` cases stay green.
- `go test ./internal/sandbox/...` (`server_test.go`): an `/execute` request carrying `ValueExpression` + `ObjectiveLabel` returns `200` with `value` keyed by the **label**; a request with neither returns `value` keyed by `Target.Field` (legacy); a request whose expression references an unknown column returns `400` with a descriptive `{"error": …}` body.
- Smoke: run the sandbox server, `POST /execute` a boolean-`avg` objective (`aggregation:"avg"`, a `Comparison`/`Cast` expression, `objective_label:"avg(Transported = True)"`) against a fixture CSV with a boolean column, expect `200` and the measured rate keyed by the label — the case that previously hard-failed with "numeric aggregation over non-numeric column."
- **Edge cases to spot-check:** empty filtered set still returns a null number (avg/sum/min/max) vs `0` (count) unchanged; a `Cast` to an unlisted type → `errUnknownCast`/`400`; a `Comparison` with an unlisted operator → `400`; the aggregation itself outside `allowedAgg` → `errUnknownAggregation`/`400` (shared with the legacy path).
