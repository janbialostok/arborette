# Plan: Verification, Refutation & the Epistemic Contract

## Context

Engine B's second stage: given a finding and the discovered graph, compute the backdoor-adjusted do() effect, stress-test it with the refutation battery, and write the result honestly — `causally_verified`, `confounded`, `not_identifiable`, or `unsupported_objective` are all first-class answers. This shell owns the whole atomic verification lifecycle: the adjustment math and its treatment/outcome mapping, refutation, the `causal_inferred` epistemic value with its read-path contract (observational collection filters + the exempt causal-evidence lookup), deterministic causal-Outcome ids with supersession on any completed outcome, and the leased, idempotent `causal_verifications` records with crash reaping and the budget/cap accounting later shells rely on.

## Resolved Open Questions

- **Refutation composition (R9/R11):** equal-weight mean of three normalized refutations, single-scalar gate `τ = 0.8`, `K = 20` subsamples.
  - `placebo = 1 − min(1, |eff_placebo| / |eff_adj|)` — a random pseudo-segment of matched support must show ~zero adjusted effect.
  - `stability = share of K subsamples whose adjusted effect keeps the full-sample sign and lands within a relative band`.
  - `randconf = 1 − min(1, |eff_randZ − eff_adj| / |eff_adj|)` — adding a synthetic random column to Z must not move the effect.
  - `score = mean(placebo, stability, randconf)`; on `causally_verified`, `confidence = score`.
  - Outcome decision order: `windowed → unsupported_objective`; `unoriented-backdoor / sparse strata → not_identifiable`; `eff_adj collapses vs naive → confounded` (independent hard trigger, contains the averaging-masks-a-blowout risk); `score ≥ 0.8 → causally_verified`; else `confounded` (naming the adjustment set). All constants are config knobs and explicit R30-calibration targets.
- **Lease duration (R12):** `VERIFIER_LEASE_TTL = 90s`, `VERIFIER_HEARTBEAT_EVERY = 30s` (lease = 3× heartbeat; two missed beats before a false reap; crashed-Verifier budget + in-flight slot recovered within ~90s).

### Convention Anchors

- Analyze kind additivity: kinds are string consts duplicated across `internal/sandbox/server.go:163` and `internal/sandboxclient/client.go:132` (byte-identical); shape validation answers **422** in `staticValidateAnalyze`, schema/type checks answer **400** via `writeStageErr` (`server.go:494-516`); caps come from config (`AnalyzeMaxColumns`/`AnalyzeMaxBins`), never literals.
- Deterministic-id + MERGE idempotency: composite-keyed nodes synthesize a hash id and MERGE on `{id}` because `InitSchema`'s id-unique constraint can't express composite keys (`causal.go:16-21`). Neo4j is a Neptune-portable openCypher subset (no APOC/`db.*`), flat primitive properties; queryable props (`epistemic_source`, `superseded`, `verification_status`) are node/edge **properties**, not JSON-blob entries.
- Postgres tables: migrations are numbered `NNNN_name.up/.down.sql` embedded via `go:embed` (`internal/store/migrations/migrations.go`); a status-machine table carries `status text NOT NULL DEFAULT 'pending'`, a `UNIQUE` doubling as an `ON CONFLICT` target, a `(goal, status, created_at DESC)` index, and **co-located GRANTs**. **Grant caveat:** the verifier connects as `arborette_service` (`cmd/verifier/main.go` `wireVerifier` uses `ServiceDSN`), which today holds only `SELECT` on `goal_registry` and `SELECT/INSERT/UPDATE` on `meta_heuristic_embeddings` (`0005_grants.up.sql`); `causal_verifications` and the new `goal_registry.verification_budget` column need explicit grants to that role.
- Store idioms: `New*(pool)` constructors; single-row claim/existence reads use `QueryRow`+`Scan` never bare `Query` (pgx defers permission errors, unread `Rows` deadlocks `Close`); `nullableText`/`marshalLocator` bind empty/nil as SQL `NULL`; nullable read columns `coalesce(...,'')`. Never hold a pooled connection while blocking.
- SSE frame contract: `writeSSEFrame` (`internal/orchestrator/stream.go:85-95`) serializes `data: <json>\n\n`, **no `event:` line** — clients discriminate on the top-level `Type` of `Event{Type, Payload}` (`hub.go:22`). Emission is `s.hub.Publish(goalID, Event{...})` (`hypothesis.go:620` etc.), paired with `recordAudit(ctx, action, eventType, detail)` (`audit.go:19`, `action` = long name, `eventType` = short category). The Hub is **in-process** — an out-of-process service reaches it only through an authenticated orchestrator endpoint (only `POST /internal/audit` crosses that boundary today, `server.go:228`).
- Seam construction: `cmd/verifier/main.go` `wireVerifier` assembles `sandboxclient`, `orchestratorclient`, `graph.Neo4jRepository`, `store.NewAdvisoryLock`, `store.NewGoalRegistry`, and a `verifier.Config` value-struct from `cfg.Verifier.*`. New knobs are `VerifierConfig` fields (`internal/config/config.go:230-243`) with `intEnv`/`floatEnv`/`env` defaults (`:405-418`), mapped into `verifier.Config`.
- Tests: sandbox analyze tests are `httptest`-driven against `NewServer` with a ground-truth parity check (`internal/sandbox/analyze_test.go` `TestAnalyzeGroundTruthParity`, importing `internal/verifier/groundtruth`); verifier regression tests generate a planted dataset via `groundtruth.Generate(groundtruth.DefaultConfig())` and score against `groundtruth.GroundTruth()` (`discovery_regression_test.go:34-88`). Demo CSV: `local-import/causal-demo.csv`.

### Proposed Alignment

This shell is almost entirely "one more instance" of existing machinery. Add the two analyze kinds by extending the `Kind` discriminator + `staticValidateAnalyze` + the `FileSource.Analyze` switch (mirroring `compileContingency`, reusing `quoteIdent` and `?`-bound literals), and duplicate the wire structs into `sandboxclient`. Build Causal Outcome/edge writes as deterministic-id MERGEs following `dataColumnID` + `CreateOutcome`/`CreateProduced`, adding `epistemic_source`/`superseded`/`verification_status` as top-level properties. Model `causal_verifications` on `verification_queue`'s guarded-UPDATE claim shape (its `UNIQUE`, co-located GRANTs, `(goal,status,created_at)` index) but grant `arborette_service` write access and use a per-goal **transaction** advisory lock for the count-guarded accept. Wire a verification worker as a twin of the discovery `Worker`, reuse `orchestratorclient` for audit + the new verification-events push, `HasWindowKind` for the short-circuit, and `internal/verifier/stats` for the refutation score. The only genuinely new surfaces are the reweighted stratified SQL and the refutation score→confidence helper.

1. **Add `stratified_effect` and `sampled_effect` analyze kinds.**

Extend `AnalyzeResponse` (`:213-217`) with `Strata []StratumRow` carrying per-stratum `{Values []string, N int64, SegmentAgg *float64, SegmentN int64, BaselineAgg *float64, BaselineN int64}` (nullable aggs for empty strata, mirroring `ExecuteResponse`'s null-number convention at `server.go:152-159`).
   - `internal/sandbox/compile.go:928`: add `stratified_effect`/`sampled_effect` cases to `staticValidateAnalyze` (adjust-column count in `[0, maxColumns]`, bins in `[2, maxBins]`, sample fraction in `(0,1]`) answering 422.
   - `internal/sandbox/compile.go`: add `compileStratifiedEffect` alongside `compileContingency` — one grouped query over the (binned) adjustment columns producing per-stratum count + segment-conditioned aggregate + baseline aggregate. The aggregate reuses the objective value-expression compiler already used by `/execute` (so the non-hallucination guarantee is identical). `sampled_effect` is the same query wrapped with `USING SAMPLE <fraction>` (DuckDB reservoir); the random-confounder variant adds the server-computed random bucket as an extra GROUP-BY term. Reuse `quoteIdent`, `compileFilters`, `binExpr`, `quantileCutsSQL`; every server-computed number (`sample fraction`, `random bins`, cut points) binds as `?` or is an integer-formatted literal, never request text.
   - `internal/sandbox/server.go` `FileSource.Analyze`: add the two cases dispatching to the new compilers.
   - `internal/sandboxclient/client.go:131-237`: mirror the new consts, request/response fields, and `StratumRow` byte-for-byte.

2. **Compute the adjustment and classify the outcome (R8/R10).**
   - New `internal/verifier/adjust.go`. **Producing the segment predicate:** read the finding's Intervention via `GetIntervention(ctx, interventionID)` (`internal/graph/neo4j.go:150`, added to the graph seam in step 4) and reconstruct the full segment conjunction as `[]domain.Constraint` from `Intervention.Properties[domain.PropEffectiveFilters]` — **not** the lossy `filterColumns` (`worker.go:406`) which yields column names only. The decoder that does this (`any → []domain.Constraint` via a JSON re-marshal, because the graph layer stores the property as JSON-decoded `[]any`-of-maps) currently lives unexported as `sleepcycle.decodeConstraints` (`internal/sleepcycle/canonical.go:137`, called in-package by `publish.go:57` and `search.go:115`). **Move it to `internal/domain` as `domain.DecodeConstraints`** — it is a pure domain operation, both `sleepcycle` and `verifier` already import `domain`, and this avoids an Engine-B→Sleep-Cycle import (and any cycle) that exporting it in place would create; update the two `sleepcycle` callers to `domain.DecodeConstraints`. Step 2 then calls `domain.DecodeConstraints`. This `[]domain.Constraint` is both the `stratified_effect` `Segment` and the source of `T`'s columns. Pin the goal's objective via `objective.Pin` on its `EvaluationMatrix`; O's columns via `expressionColumns` (`worker.go:374-401`). Short-circuit: `domain.HasWindowKind(objective expression)` → `unsupported_objective` before any query.
   - Read the committed causal graph (`graphWriter.GetCausalGraph`), derive `T` = segment filter columns, `O` = objective value-expression columns, `Z = parents(T) \ (T ∪ O)` (directed `CAUSES` edges into any T column). If any edge on a backdoor path incident to T or Z is unoriented (`EdgeStatus` unknown/undirected) → `not_identifiable`.
   - Call `stratified_effect` over Z with the segment predicate. Reweight in Go: `eff_adj = Σ_z SegmentAgg(z)·(N(z)/ΣN)`; naive = the unstratified within-segment aggregate (one plain `/execute` or a Z-less stratified call). **The support floor gates on the treated count, not the stratum total:** a stratum passes only when `SegmentN` (and `BaselineN` for the baseline arm) ≥ `VERIFIER_SUPPORT_FLOOR` (shared with discovery's floor semantics) — a stratum with large total `N` but `SegmentN = 0` is a positivity violation, so gating on `N` would admit it and leave `SegmentAgg` null. Any Z-stratum failing this treated-count floor, **or** any above-floor stratum returning a null `SegmentAgg`/`BaselineAgg`, → `not_identifiable` (never silently dropped — dropping it would bias `eff_adj`). If `eff_adj` collapses relative to naive (config `VERIFIER_COLLAPSE_RATIO`, e.g. adjusted retains < 50% of naive marginal effect toward the objective direction) → `confounded`, naming Z. Effect sign/magnitude uses `objective.Improves`/`NumericValue` for direction consistency.

3. **Refutation battery and score→confidence (R9).**
   - New `internal/verifier/refute.go` + a score helper in `internal/verifier/stats/`. Three refutations against the surviving adjusted effect:
     - **placebo:** build a random pseudo-segment predicate of matched support (draw a column/value combination from `Introspect` distinct values whose support ≈ the real segment's), run `stratified_effect`, `placebo = 1 − min(1, |eff_placebo|/|eff_adj|)`.
     - **subsample stability:** `K = VERIFIER_REFUTATION_K` (20) `sampled_effect` calls at `SampleFraction` (config, e.g. 0.7); `stability = share keeping the full-sample sign and within the relative band VERIFIER_STABILITY_BAND`.
     - **random-confounder:** `stratified_effect` with `RandomStratifierBins` added to Z; `randconf = 1 − min(1, |eff_randZ − eff_adj|/|eff_adj|)`.
   - `score = mean(placebo, stability, randconf)` (`internal/verifier/stats/refutation.go`, keeping the verifier CGO-free). `score ≥ VERIFIER_REFUTATION_TAU` (0.8) → `causally_verified` with `confidence = score`; else `confounded` naming Z.

The forward-compat rule (absent → observational) is unchanged.

Leave `TraceCausalChain` (`:618`) returning both, and label each triplet's edge with its `epistemic_source` in `tripletFromRecord`.
   - Add the **exempt causal-evidence lookup** `GetCausalEvidence(ctx, interventionID) (CausalEvidence, bool, error)` reading only `epistemic_source = 'causal_inferred'` edges, `superseded <> true`, latest by graph version — the distinct read path R16/R25/R33 consume. It ignores the observational filter by construction.
   - **Seam:** extend the Worker's graph seam (the `graphWriter` interface, `internal/verifier/worker.go:44-51`) with **four** new methods — `GetIntervention` (step 2's segment-predicate producer), `GetCausalEvidence`, and the two step-5 writers — so `VerifyOne` can reach them; `*graph.Neo4jRepository` already satisfies the wider surface (all four exist or are added on it). 5. **Write causal Outcomes with deterministic ids and universal supersession (R11).**
   - `internal/graph/causal.go`: add `causalOutcomeID(interventionID string, version int) string = hashID(interventionID, strconv.Itoa(version))`.
   - Add `WriteCausalVerification(ctx, interventionID string, version int, outcome domain.Outcome, edge domain.ProducedEdge)` performing, in one `writeOp`: MERGE the causal Outcome on `causalOutcomeID` (`verification_status = verified`, adjusted effect in `value`), MERGE the `PRODUCED` edge with `epistemic_source = causal_inferred`, `confidence = score`, `superseded = false`, and in the **same** write mark every prior `causal_inferred` edge for that intervention (older version, `superseded <> true`) `superseded = true`.
   - Add `SupersedePriorCausalOutcomes(ctx, interventionID string, version int)` — the standalone retraction write for non-confirming results (`confounded`/`not_identifiable`/`unsupported_objective`): marks prior causal edges `superseded = true` with **no** new edge, so a correction that invalidates a claim removes it from serving. Both writers touch only `causal_inferred` edges; observational edges are never modified.
   - **Seam:** both writers join the extended `graphWriter` interface (step 4) alongside `GetIntervention`/`GetCausalEvidence`, so `VerifyOne` reaches all four new methods through the one graph seam it already holds.

6. **Build the `causal_verifications` store with leases, budget, and cap (R12).**
   - New migration `internal/store/migrations/0013_causal_verifications.up/.down.sql`: table `causal_verifications(id, goal_id, intervention_id, graph_version, status, naive_effect, adjusted_effect, adjustment_set jsonb, refutation_score, confidence, budgeted bool, stale bool, lease_deadline timestamptz, created_at, updated_at)`; `status` ∈ `pending|causally_verified|confounded|not_identifiable|unsupported_objective|failed` default `pending`; `UNIQUE (goal_id, intervention_id, graph_version)` (R12 idempotency); index `(goal_id, status, created_at DESC)`. Also `ALTER TABLE goal_registry ADD COLUMN verification_budget INTEGER` (config-defaulted; **this shell adds only the budget column** — shell 08 adds `track`/`extracted_claim`, an additive seam). Co-locate only `GRANT SELECT, INSERT, UPDATE ON causal_verifications TO arborette_service;`. **No new `goal_registry` grant is needed:** `arborette_service` already holds `SELECT` on `goal_registry` (`0005_grants.up.sql`), which is all the verifier needs — the budget is enforced by row-counting, never a column decrement, and the column is written by the orchestrator role at registration (shell 08).
   - New `internal/store/causalverifications.go` (`New*(pool)` convention). Verbs:
     - `DispatchAccept(ctx, rec) (CausalVerification, accepted bool, err error)` — the transactional charge-at-accept. `rec` carries the fully-determined `(goal_id, intervention_id, graph_version)` key (the caller resolves `graph_version` before dispatch — see `VerifyOne` in step 7). In one `pgx.Tx`: take `pg_advisory_xact_lock(hash(goal_id))` (transaction lock, auto-released at commit — sidesteps the session-lock connection-pinning gotcha); coalesce on the unique key — a live (`pending`) or completed record is returned with **`accepted = false`** (R12 duplicate-dispatch coalescing: the caller must not re-run it); a fresh insert or a `failed` record **re-leased** via `UPDATE failed → pending` with a fresh `lease_deadline` returns **`accepted = true`**. Before an insert or re-lease, enforce the in-flight cap (`count(status='pending') < VERIFIER_INFLIGHT_CAP`, all dispatches) and, when `budgeted`, the budget. The per-goal budget value is read **inside the same transaction by joining `goal_registry`** (`SELECT verification_budget FROM goal_registry WHERE optimization_function_id = rec.goal_id`, `coalesce`-defaulted to the config `VerificationBudget` when the column is NULL) — not taken from `rec` — so a concurrent dispatch cannot race a stale budget; the guard is then `count(budgeted AND status <> 'failed') < verification_budget`. Charge is uniform at accept (insert or re-lease); return a typed `ErrBudgetExhausted`/`ErrInflightCapReached` the dispatcher maps to a first-class outcome.
     - `Heartbeat(ctx, id)` — `UPDATE ... SET lease_deadline = now() + ttl WHERE id = $1 AND status = 'pending'`.
     - `Complete(ctx, id, status, effects...)` — guarded `UPDATE ... WHERE id AND status='pending'` stamping the terminal status; `RowsAffected()==0` means the lease was reaped mid-run (do not overwrite `failed`).
     - `ReapExpired(ctx)` — `UPDATE pending → failed WHERE lease_deadline < now()`, refunding budget/cap implicitly (the count guards exclude `failed`). Runs on a ticker in serve mode and lazily inside `DispatchAccept`.
     - `MarkStale(ctx, goalID, adjustmentColumnsTouchingEdge)` — sets `stale = true` for R7 (shell 08 dispatches the re-verification; a bumped graph version makes it a new key, not a duplicate).
     - `ListForGoal(ctx, goalID)` — powers the orchestrator's `GET /goals/{id}/verifications`.

7. **Wire the verification worker + stream and audit every transition (R12).**
   - `internal/verifier/verify.go`: a `VerifyOne(ctx, goalID, interventionID, datasourceRef string, budgeted bool)` on `Worker` (twin of `RunDiscovery`), in this order:
     1. **Resolve the graph version first.** Read the current committed version via `GetCausalGraph(goalID, datasourceRef)`; if no graph exists yet, use the fixed `discoveryVersion = 1` (`worker.go:110` — version bumping is a later shell). This fully determines the `(goal, intervention, graph_version)` key before accounting, so DispatchAccept's coalesce/unique key is correct even though the graph itself is (re)ensured below.
     2. **`DispatchAccept(rec{…, graph_version})`.** If `accepted == false` (coalesced to a live or completed record), **return early** surfacing that record — no run, no ticker, no duplicate SSE/audit. Only `accepted == true` proceeds.
     3. **Start the `Heartbeat` ticker (every `HeartbeatEvery`, 30s) immediately**, before anything else in the leased window, and stop it in a `defer`. It must precede ensure-graph because a **first** verification runs full causal discovery inline — bounded by `RunDiscovery`'s 30-min wait budget (`worker.go:102`), far longer than the 90s lease — so without heartbeat coverage the lease would expire, `ReapExpired` would flip the live record to `failed`, and the terminal write would no-op, silently discarding a valid result.
     4. Ensure a graph exists (reuse `RunDiscovery`'s single-flight) → adjustment (step 2) → refutation (step 3), yielding the terminal status + effects.
     5. **Claim-then-write.** Call `Complete(id, status, effects…)` **before** any graph write — its guarded `UPDATE … WHERE status='pending'` doubles as an ownership re-check. Only if `Complete` reports `RowsAffected == 1` (we still hold the lease) does `VerifyOne` perform the graph write: `WriteCausalVerification` on `causally_verified`, else `SupersedePriorCausalOutcomes`. `RowsAffected == 0` (the lease was reaped to `failed` and its budget/cap refunded) **skips the graph write entirely**, so a served `causal_inferred` edge is never left backed by a `failed` record.
