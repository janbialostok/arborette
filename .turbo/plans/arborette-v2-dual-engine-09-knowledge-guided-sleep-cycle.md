# Plan: Knowledge-Guided Sleep Cycle (UCT-MCTS)

## Context

The Sleep Cycle's search stops being bounded by whatever vocabulary Phase 1 happened to surface: schema-derived atoms make the lattice genuinely large, and the growing Meta-Heuristic graph supplies both expansion proposals (grounded heuristics — the deferred Cold-Start reuse path) and selection priors, with causal evidence multiplying value estimates. The result is the compounding property that is V2's search thesis: the more knowledge accumulates, the better search gets. Everything lands behind the existing `SearchPolicy` seam — driver, measurement, budgets, and write-back are unchanged — and the beam ships as default until UCT passes the calibration gate against the ground-truth dataset (spec R14 acceptance).

Settled constants (escalated at expansion): exploration constant starts at √2 behind `SLEEPCYCLE_SEARCH_UCT_C` and is pinned by the calibration gate; the causal multiplier is confidence-weighted, `1 + scale·Confidence` (absent evidence = exactly ×1), scale behind a knob; priors decay PUCT-style (prior term weighted by √N_parent/(1+n_child)); the atom/grounding expansion budget is a fixed gate-calibrated ratio behind a knob, with grounding falling back to atoms when retrieval returns nothing.

Plan risks found during expansion (noted, all additive):

- `EmbeddingStore.SimilaritySearch` returns only node ids (`internal/store/embeddingstore.go:214`) — UCT similarity priors need distances, so a scored variant is added (Step 5).
- Quantile cuts have no introspection path — `quantileCutsSQL` (`internal/sandbox/compile.go:1002`) lives only inside the analyze path; introspect exposes only `DistinctValues`. An opt-in introspect extension is added (Step 2). `internal/sleepcycle` must consume it via `internal/sandboxclient` DTOs only — importing `internal/sandbox` from a non-CGO service redefines wire DTOs and breaks the CGO-free build guard.
- `SearchPolicy` implementations never talk to the sandbox or do I/O (contract at `internal/sleepcycle/search.go:47-58`), so all retrieval, LLM grounding/critique calls, and causal-evidence lookups happen in the worker run flow before the policy is constructed; the policy receives them as plain data.

## Pattern Survey

### Analogous Features
- `internal/sleepcycle/beam.go:29-225` — `beamPolicy`, the sole existing `SearchPolicy` implementation. Select/Update/Done + eager level advance in `Update`, level-wise expansion (`expand`/`conjoin`), Apriori/width pruning (`prunedBySubset`/`frontier`). The uctPolicy is a second implementor of the identical interface and should mirror this file's structure (constructor takes `atoms, cfg, baseline, direction`, memo map, directional-delta ranking).
- `internal/sleepcycle/search.go:59-67` — `SearchPolicy` interface + its seam contract (lines 47-67): driver owns measurement/memo/budget/winners; policy owns candidate generation only, never touches the sandbox. The contract explicitly anticipates a re-selecting V2 policy ("the V2 seam's whole point," beam.go:96) — UCT re-selection is already accounted for by the driver's memo (`runSearch`, search.go:189-195).
- `internal/sleepcycle/search.go:112-143` — `buildAtoms`, the current atom vocabulary source (derived from Phase-1 findings' `PropNewFilters`). The schema-derived-atom flag is a parallel/alternative vocabulary feeding the same `[]atom` shape (key/rank/constraint/sourceIDs); atoms are ranked by `strings.Compare` on canonical key, rank = sort index.
- `internal/llm/orient.go:48-56`, `classify.go:61-69`, `client.go:181-189` — the three-line LLM-call idiom every structured-output call follows: `NewFence(label)` → `backend.complete(ctx, system+fence.Directive(), prompt, schema())` → `decodeX(body)`. `CritiqueAtoms` and `GroundHeuristic` should be new methods in this exact shape (new `*_system` const, `*Schema()` in schema.go, `decodeX` with deterministic post-validation).
- `internal/llm/classify.go:71-148` + `schema.go:150-164` — the reify-a-filter-conjunction-through-a-JSON-string pattern: growing/dataset-dependent value sets ride as a `claim_filters` plain-string field decoded via `filterWire.toConstraint()`, NOT as a strict-schema array (grammar-ceiling avoidance). Any grounding/critique call that emits filters must reuse this, not a new enum schema.
- `internal/graph/causal.go:31-122` — `GetCausalEvidence` (single) and `CausalEvidenceForHeuristics` (batch) return `CausalEvidence{EffectSize, Confidence, GraphVersion}` keyed by id; the latter picks the strongest surviving edge per heuristic. This is the causal-multiplier lookup for UCT backprop; the batch form is the one to use so the multiplier is one query, not per-node.
- `internal/verifier/discovery_regression_test.go:34-70` + `verify_regression_test.go` — the calibration-gate template: `groundtruth.Generate(DefaultConfig())` → in-process fake analyzer → run → assert precision/recall/status thresholds pinned "from the first honest run with slack." The UCT-vs-beam gate belongs here (fake sandbox over the planted dataset, assert UCT winners ⊇ beam winners at default budget).
- `internal/graph/causal.go:324-404` (`CorrectCausalEdge`) — the persisted-ontology-terms-at-abstraction-time analogue: copy-forward-at-version+1 under caller-held lock, commit-marker (meta) last. Node-property additions on MetaHeuristic follow neo4j.go:329-338's MERGE/ON-CREATE-SET/FOREACH-heal idiom instead.

- `internal/domain/domain.go:653` — `UnknownFilterValues(filters, values map[string][]string)` — value-set grounding (eq/neq/in/not_in against distinct values), returns `column=value` offenders. This is the validation for enum-derived atoms and grounded instantiations.
- `internal/sleepcycle/canonical.go:28` — `CanonicalFilters` / `canonicalComponents` / `canonicalKeyOf` (beam.go:220) — the order/duplicate-insensitive predicate-set key. The no-same-(field,op) invariant guard belongs at `conjoin`/expansion time in both policies, keyed off these.
- `internal/domain/domain.go:553` — `domain.Constraint` + `IsNumericThresholdOp/IsEqualityOp/IsMembershipOp` — the field/op predicates the conjunction invariant tests against.
- `internal/domain/score.go` (`domain.ShrunkScore`, `domain.DirectionalDelta`, `domain.Improves`) — evidence-weighted scoring already shared by beam frontier and publish; UCT value estimates/backprop should reuse `DirectionalDelta`/`ShrunkScore` rather than invent a value function.
- `internal/llm/fence.go:29-55` — `NewFence(label)` / `Wrap` / `Directive` — mandatory per-request random-delimiter fencing for ALL untrusted text (goal text, column names, prior LLM output). Every new LLM call (critique, ground) must fence its inputs and append `Directive()` to the system prompt.
- `internal/llm/abstract.go:50` — `LeakedConcreteTerms(def, columns)` — word-boundary column-leak check; reusable for critique-atom leakage/tautology exclusion.
- `internal/config/config.go:489-523` — `env`, `intEnv`, `int64Env`, `floatEnv`, `boolEnv` — the env-parsing helpers. `SLEEPCYCLE_POLICY` (a string enum) uses `env("SLEEPCYCLE_POLICY", "beam")`; schema-atom flag uses `boolEnv`.
- `internal/heuristics/service.go:73` — `Service.Query(ctx, stateString, k, scope)` with `store.ScopeFromGoalID` / `store.SearchScope` (embeddingstore.go:166-191, `CrossGoal` vs `GoalID`) — the goal-scoped/cross-goal similarity retrieval the grounding "retrieval move" and UCT similarity priors build on; distance floor is store-side (`distanceFloor`, embeddingstore.go:17).

### Convention Anchors
- **Config isolation**: search tuning is a package-local `sleepcycle.Config` (worker.go:51), NOT `config.SleepCycleConfig`, so `internal/config` stays a `cmd/`-only dependency (worker.go:48-50). A `Policy string` field (and schema-atom flag) is added to BOTH `config.SleepCycleConfig` (config.go:211) and `sleepcycle.Config`, translated in `cmd/sleepcycle`. Validate new knobs in `Config.validate()` (worker.go:60) so a bad value fails at startup.
- **Env naming**: search knobs carry the `SLEEPCYCLE_SEARCH_` prefix (`SLEEPCYCLE_SEARCH_BEAM_WIDTH`, etc., config.go:436-441); non-search stage knobs drop `SEARCH` (`SLEEPCYCLE_MAX_PUBLICATIONS`). `SLEEPCYCLE_POLICY` is stage-level (selects the driver), so no `SEARCH` segment.
- **Consumer-defined narrow interfaces**: `Worker`'s deps (`searchRepo`, `sandboxExecutor`, `claudeClient`, worker.go:83-119) are declared at the consumer for fake-based unit tests. A new causal-evidence lookup or grounding LLM call is added as a method on these existing interfaces, not a new struct dependency.
- **Structured-output schema discipline** (schema.go:52-164): strict schema holds ONLY small fixed enums; growing/dataset-sized value sets and recursive ASTs ride as prompt-grounded JSON-encoded plain strings, parsed + validated deterministically after decode. Keeps the schema static/cacheable. Critique/ground schemas must follow this.
- **Per-item failure isolation + audit-report idiom**: every stage isolates failures per candidate/segment and calls `w.report(ctx, action, eventType, detail)` (worker.go:425) which logs-and-swallows. New provenance/trace surfacing threads through these audit details (e.g. abstract.go:175 `abstracted_from`), and `optimization_function_id`/nil-not-"" id conventions apply.
- **Additive graph node properties**: written via MERGE + `ON CREATE SET`/`ON MATCH SET` + standalone `FOREACH (_ IN CASE …)` for conditional heals (neo4j.go:329-338); MERGE-on-deterministic-id makes re-runs idempotent. Persisted OntologyTerms/origin on MetaHeuristic nodes follow this, not in-place edits.
- **Integration/regression gating**: `internal/testutil` skips unless `ARBORETTE_INTEGRATION=1` (testutil.go:24); pure-compute regression gates (discovery/verify) run in-process against `groundtruth.Generate` with NO env gate. The UCT calibration gate is the latter kind (no Neo4j/DB), matching `discovery_regression_test.go`.

### Proposed Alignment
Follow the existing patterns closely — the seam was explicitly built for this. `uctPolicy` is a second `SearchPolicy` mirroring `beamPolicy`'s file/constructor/memo structure; the driver, `measure`, write-back, and publish stages need no changes (search.go:47-67 already tolerates re-selection via the driver memo). New LLM calls (`CritiqueAtoms`, `GroundHeuristic`) reuse the fence→`backend.complete`→deterministic-decode idiom and the JSON-encoded-filter-string convention for any dataset-sized output; grounding validation reuses `UnknownFilterColumns`/`UnknownFilterValues` (drop-not-repair). Config, env-naming, and calibration-gate structure all have direct templates.

## Implementation Steps

1. **Persist ontology terms + origin on Meta-Heuristic nodes at abstraction time (R15 acceptance)**
   - Add `domain.OntologyTerm{Concrete, Ontological string}` and extend `domain.MetaHeuristic` (`internal/domain/domain.go:145`) with `OntologyTerms []OntologyTerm`, `OriginGoalID string`, `OriginDataSourceRef string`. `internal/llm` keeps its own `OntologyTerm` (`abstract.go:27`); `internal/sleepcycle/abstract.go` converts between them (domain must not import llm).
   - Extend `CreateMetaHeuristic` (`internal/graph/neo4j.go:294`): write `ontology_terms` as a JSON-encoded string property (Neo4j properties cannot nest), plus `origin_goal_id` and `origin_datasource_ref`, on `ON CREATE SET`, with a match-side heal via standalone `FOREACH (_ IN CASE WHEN $terms <> '' …)` guarded on non-empty — same idiom as the existing `goal_id` heal at neo4j.go:333, so a term-less re-link caller can never blank persisted terms. Decode the three properties in every MetaHeuristic read path (`GetMetaHeuristic`, `GetMetaHeuristics`, `ListMetaHeuristics`).
   - Thread the data in `abstractOne` (`internal/sleepcycle/abstract.go:56,105`): populate the new `domain.MetaHeuristic` fields from `llm.Abstraction.OntologyTerms` and `target` (`goalID`, `dataSourceRef` — both on `searchTarget`). The existing-node re-link branch (abstract.go:70) passes existing terms through unchanged.
   - Integration test in `internal/graph` (gated `ARBORETTE_INTEGRATION=1` via `internal/testutil`): create → read round-trips terms + origin; re-link without terms does not erase them.

2. **Schema-derived atom vocabulary behind a flag, with the CritiqueAtoms critic (R18)**
   - Extend introspect with opt-in quantile cuts: `sandboxclient.IntrospectRequest` gains `QuantileBins int` (0 = current behavior, fully additive) and `sandboxclient.Column` (`client.go:39`) gains `QuantileCuts []float64`; mirror both on the sandbox wire structs in `internal/sandbox/server.go` (byte-for-byte JSON-compatible, per the existing DTO-copy rule). The sandbox handler computes cuts per numeric column by reusing `quantileCutsSQL` (`internal/sandbox/compile.go:1002`), skipping columns whose quantiles come back NULL.
   - New `buildSchemaAtoms(schema, bins)` in `internal/sleepcycle` (alongside `buildAtoms`, search.go:112): enum atoms from `Column.DistinctValues` (`eq` per value), threshold atoms from `QuantileCuts` (`lte`/`gt` per interior cut); keys via `CanonicalFilters`; `sourceIDs` left empty — enumerated atoms carry no fabricated Phase-1 provenance, so a winner built only from them gets `abstractedFrom` links only to its own derived triplet nodes (the existing `candidatesFromWinners` path already tolerates empty atom sources).
   - New `CritiqueAtoms` in `internal/llm/critique.go` following the orient/classify idiom (`orient.go:48-56`): fenced goal text + column list (`NewFence` + `Directive()`), strict schema holding only small fixed fields, with the excluded-column list and optional first-level ranking riding JSON-encoded string fields per the schema discipline (`schema.go:150-164`); deterministic post-validation drops any excluded/ranked name not in the real column set. One call per run, flagging leakage/tautology columns (IDs, post-outcome columns, objective correlates) for exclusion.
   - Wire behind `SLEEPCYCLE_SEARCH_SCHEMA_ATOMS` (boolEnv, default false): in the worker run flow (`worker.go:266` area), first drop every schema-derived atom whose `Constraint.Field` is in the critic's validated exclusion set — exclusion applies to the schema-derived vocabulary only; findings-derived atoms are measured Phase-1 evidence and are never removed by the critic — then merge the surviving `buildSchemaAtoms` output into `buildAtoms` output, deduplicating on canonical key with findings-derived provenance winning; re-rank the merged set. Add `CritiqueAtoms` to the `claudeClient` interface (worker.go:102). Audit the critic's exclusions, the count of atoms they dropped, and the merged atom counts via `w.report`.
   - A critic-call failure degrades: log + audit, proceed with findings-derived atoms only (per-item failure isolation convention).

3. **Policy-contract invariant: no same-(field,op) conjunction (R17)**
   - Document the invariant on the `SearchPolicy` interface comment (`internal/sleepcycle/search.go:47-67`): no generated candidate conjoins two atoms sharing a `(field, op)` pair.
   - Shared guard `conflictsWithNode(node, atom) bool` in `internal/sleepcycle` comparing `(Constraint.Field, Constraint.Op)` pairs; applied in beam's `expand` (`beam.go:162`, alongside the rank check) and in uct's expansion move generation.
   - Table-driven tests per implementation (beam and uct) proving a same-(field,op) pair is never generated — including the schema-atom case where one column contributes many `eq` atoms and many `lte` cuts.

4. **Implement `uctPolicy` (R14, R16)**
   - New `internal/sleepcycle/uct.go`: `uctPolicy` implementing `Select`/`Update`/`Done`, constructed as `newUCTPolicy(atoms []atom, proposals []groundedProposal, priors map[string]float64, evidence map[string]graph.CausalEvidence, cfg Config, baseline float64, direction domain.TargetDirection)` — all knowledge passed in as data; the policy does no I/O (seam contract, search.go:47-58).
   - Selection: PUCT — descend from the root choosing `argmax(Q(child) + c·P(child)·√N(parent)/(1+n(child)))` with `c = cfg.UCTExploration` (default √2). `P` comes from the constructor's `priors` map, keyed by move identity: an atom move keys on the atom's canonical key, a grounded-proposal move on its `heuristicID`. Producers: proposal priors are the retrieval similarity (`1 − distance/2`, Step 5); atom priors come from the Step-2 critic's optional first-level ranking, mapped to canonical keys (rank → descending prior mass); any unranked/unmatched move gets a uniform floor prior, so an empty critic ranking or empty corpus degrades to plain UCT. `Select` returns the first unmeasured node on the chosen path; re-selection of a measured node is free (driver memo, search.go:189-195) and `Update` must be idempotent per canonical key exactly as beam's is (beam.go:97-101).
   - Backprop in `Update`: node value = `domain.DirectionalDelta(m.Value, baseline, direction)` evidence-weighted via `domain.ShrunkScore` against `m.Support`, multiplied by the causal multiplier `1 + cfg.CausalMultiplierScale·Confidence` when any constituent atom's `sourceIDs` (Phase-1 intervention ids) or proposing heuristic id has an entry in the evidence map — absent evidence is exactly ×1, which is also the R13 additivity rule for this stage: a finding with unknown or missing epistemic provenance scores as plain observational, never as causally supported. Failed/below-floor measurements backprop as non-expandable (Apriori still holds: reuse `prunedBySubset`-style subset evidence to refuse expanding a node whose measured subset fell below `MinSupport`).
   - Expansion: moves are (a) conjoin-an-atom (respecting the Step-3 invariant and `MaxOrder`) and (b) adopt-a-grounded-proposal (a full conjunction from Step 5, entering as a node whose parent is root); per-expansion budget split fixed at `cfg.GroundingFraction` (default 0.3) grounding moves, falling back to atom moves when proposals are exhausted or empty.
   - Termination: `Done` when no unmeasured candidate remains within `MaxOrder` — the driver's `MaxMeasurements` budget and context check bound the run regardless (search.go:170-186).
   - Config: add `Policy string`, `SchemaAtoms bool`, `UCTExploration float64`, `CausalMultiplierScale float64`, `GroundingFraction float64`, `RetrievalK int`, `QuantileBins int`, `CrossGoalGrounding bool` to `sleepcycle.Config` (worker.go:51) with `validate()` rules (worker.go:60: policy ∈ {beam, uct}, c > 0, scale ≥ 0, fraction ∈ [0,1], k ≥ 1, bins ∈ {0} ∪ [2..]; booleans need no rule); mirror all eight on `config.SleepCycleConfig` (config.go:211) parsed at config.go:436-441 (`SLEEPCYCLE_POLICY` default "beam", `SLEEPCYCLE_SEARCH_UCT_C` default 1.4142135, `SLEEPCYCLE_SEARCH_CAUSAL_MULT_SCALE` default 1.0, `SLEEPCYCLE_SEARCH_GROUNDING_FRACTION` default 0.3, `SLEEPCYCLE_SEARCH_RETRIEVAL_K` default 8, `SLEEPCYCLE_SEARCH_QUANTILE_BINS` default 4, `SLEEPCYCLE_SEARCH_SCHEMA_ATOMS` default false, `SLEEPCYCLE_SEARCH_CROSS_GOAL` default true — see Step 5); translate in `cmd/sleepcycle`.
   - Policy selection in the worker run flow (worker.go:277): `newBeamPolicy` vs `newUCTPolicy` switched on `cfg.Policy`. Under `uct`, the formability decision nests so its cheap clauses short-circuit before any grounding spend — `bestSingle` is already computed before `buildAtoms` (worker.go:264), so: `if MaxOrder < 2 || bestSingle == nil → skip (no pre-fetch at all); else pre-fetch grounding + causal evidence; if merged atoms < 2 AND no validated grounded proposal → skip; else search`. Today's guard `if len(atoms) < 2 || w.cfg.MaxOrder < 2` (worker.go:275) counts only atoms, which would skip the whole branch — grounding included — on a sparse-findings goal, exactly the Cold-Start case grounding exists for; the atoms/proposal clause fixes that, and only that clause needs the pre-fetch. Proposal validation (Step 5) already bounds order to `2 ≤ order ≤ MaxOrder`, so a validated proposal is admissible by construction; beam keeps the existing guard unchanged. The `bestSingle == nil` short-circuit exists because `materiallyBetter` deliberately discards every winner when S* is undefined ("nothing can clear the bar and nothing is written back"), so searching a pure-cold-start goal (no finding clearing `MinSupport`) would spend sandbox budget and LLM grounding calls on structurally-unpersistable results — the nesting is what actually realizes that saving. Cold-Start reuse therefore functions on goals with at least one qualifying finding; the pure-zero-S* goal keeps today's skip (with `search_skipped` naming the reason), a documented limitation of this shell rather than a silent one — lifting it would mean an S*-independent write-back, a deliberate V1-gate change out of scope here (R14: write-back unchanged). Before constructing uct, the worker pre-fetches (i) similarity priors + grounded proposals (Step 5) and (ii) causal evidence — a new batched `CausalEvidenceForInterventions(ctx, interventionIDs) (map[string]CausalEvidence, error)` in `internal/graph/causal.go` (mirroring `CausalEvidenceForHeuristics`, `causal.go:75`, minus the heuristic hop — one query for all eligible findings' intervention ids, latest non-superseded edge each; the single-id `GetCausalEvidence` at `causal.go:31` stays for other callers) plus `CausalEvidenceForHeuristics` for the retrieved heuristic ids, both added to the `searchRepo` interface (worker.go:83). A failed pre-fetch degrades to empty maps (log + audit), never aborts the run.

5. **Implement grounding: retrieval → instantiation → validation → provenance (R15, R19)**
   - Scored retrieval: add `SimilaritySearchScored(ctx, query, k, scope) ([]ScoredRef, error)` to `EmbeddingStore` (`internal/store/embeddingstore.go:214` pattern: same tx, `SET LOCAL hnsw.iterative_scan`, distance floor, per-scope SQL) where `ScoredRef{NodeID string, Distance float64}`; similarity prior = `1 − distance/2` (cosine distance ∈ [0,2]). Extend the worker's `embeddingStore` interface (worker.go:107) with it. Retrieval query text = the goal's text embedded via the existing `embedding.Provider.EmbedQuery`; scope = `CrossGoal` by default — R25 names R15 grounding as the canonical explicitly-requested cross-goal reuse ("queries filter by goal unless cross-goal reuse is explicitly requested, as in R15 grounding"), and goal-scoped grounding would be largely redundant with the atom search (one goal = one datasource), leaving the Cold-Start path inert. `SLEEPCYCLE_SEARCH_CROSS_GOAL` (boolEnv, default true) stays as an operational kill-switch restricting grounding to `store.ScopeFromGoalID(goalID)` when false.
   - Load the retrieved heuristics: turn the `ScoredRef` node ids into full `domain.MetaHeuristic` records — including the Step-1 `OntologyTerms`/`OriginGoalID`/`OriginDataSourceRef` — in one call by adding the existing batched `GetMetaHeuristics(ctx, ids)` (`internal/graph/neo4j.go`, already consumed by `heuristics.Service.Query` at `internal/heuristics/service.go:82`) to the worker's `searchRepo` interface (worker.go:83). This loaded record is what the same-vs-cross-dataset routing below reads; no per-id `GetMetaHeuristic` loop.
   - Same-dataset instantiation: for a retrieved heuristic whose persisted `OriginDataSourceRef` equals the target's, fetch its source conjunctions via a new `graph` read `AbstractionSourceFilters(ctx, mhID)` (walk `ABSTRACTED_FROM` to Interventions, decode `PropNewFilters` with `domain.DecodeConstraints`) and confirm every bracketed term in the definition resolves through the persisted `OntologyTerms` map — the term map is the same-dataset identity check R15 names.
   - Cross-dataset / pre-V2 (origin differs, or no persisted terms): new `GroundHeuristic` in `internal/llm/ground.go` — fenced heuristic definition + its term pairs + the target's column names and distinct values; output filters ride the JSON-encoded-string field decoded via the `filterWire.toConstraint()` path (`classify.go:71-148`), never a strict-schema array.
   - Both paths validate deterministically before entering search: `domain.UnknownFilterColumns` against introspected columns, `domain.UnknownFilterValues` against `DistinctValues`, no two constraints sharing a `(field, op)` pair (the R17 invariant applies to adopted proposals too — they enter as full conjunctions and never pass through `conflictsWithNode`, so this is the only place it can hold for them), and conjunction order within `2 ≤ order ≤ MaxOrder`; any offender drops the proposal (dropped-not-repaired, R15 acceptance), audited via `w.report` with the heuristic id. The R17 per-policy test (Verification) must cover the adopted-proposal path, not just atom conjunction.
   - Provenance: `groundedProposal{filters []domain.Constraint, heuristicID string, prior float64}`; `Node` gains a `proposedBy string` field carried through `measuredNode` → `winner` → `writeSegment` (`internal/sleepcycle/writeback.go:76`), written as `proposed_by_meta_heuristic_id` in the derived Intervention's `Properties` map and included in the `sleepcycle_intervention` audit detail — `trace_causal_chain` then shows knowledge reuse (R19) with no graph-schema change (open properties map).

6. **Calibration gate + default flip (R14 acceptance, R30 partial)**
   - New `internal/sleepcycle/uct_calibration_regression_test.go` modeled on `internal/verifier/discovery_regression_test.go:34-70`: generate the planted dataset in-process via `internal/verifier/groundtruth.Generate(DefaultConfig())`; drive `Worker.runSearch` with a fake `sandboxExecutor` whose `Execute` evaluates filter conjunctions + the objective aggregation over the generated rows in Go (extend `fakes_test.go`); run beam and uct at the default `MaxMeasurements` budget with identical atoms; assert uct's winner set matches or beats beam's — every beam winner's segment is found by uct with equal-or-better directional delta, and uct finds the planted interaction effect (the R30 conjunction-only signal). No env gate — pure compute, like the discovery regression.
   - Calibrate the constants against this gate (c, causal-multiplier scale, grounding fraction, quantile bins): pin the passing defaults in `internal/config/config.go` and `sleepcycle.Config`, with the regression asserting at exactly those defaults, "from the first honest run with slack."
   - Wire the default flip: once the gate passes at defaults, flip `env("SLEEPCYCLE_POLICY", "beam")` → `"uct"` (config.go:436-441 block) in the same change that lands the passing regression, so the flip and its evidence are one commit. If calibration cannot beat beam on the gate dataset, the default stays "beam" and the flip is deferred — the policy, flag, and gate still land.
