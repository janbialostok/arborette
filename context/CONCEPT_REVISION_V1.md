# System Specification: Automated Causal Abstraction Engine (ACAE)
### Tagline: A system which automatically builds domain expert-level knowledge Agents.

---

## 1. System Overview & Phased Implementation
The Automated Causal Abstraction Engine (ACAE) empowers non-technical analysts to build and seed cross-domain knowledge graphs without writing code. 

To ensure rapid time-to-value and manage infrastructure complexity, the system is being implemented in two phases:
*   **V1 (Current Target):** Fast, observational hypothesis testing (SQL/Segmentation) coupled with an advanced State-Space Search and Ontological Abstraction "Sleep Cycle."
*   **V2 (Roadmap):** A Dual-Engine Episodic layer introducing active, sandboxed state-search execution and a Control Plane Router.

This document serves as the architectural blueprint for the V1 implementation and the V2 transition state.

---

## 2. V1 Interaction Model: Observational Episodic & Active Sleep Cycle

In V1, the system relies on read-only database operations to rapidly mine data, while reserving heavy state-space search for the asynchronous background consolidation phase. This completely decouples the user-facing latency from the complex graph math.

### Phase 1: The Episodic Memory Layer (Fast SQL / Greedy Search)
The analyst defines a goal in natural language (e.g., *"Maximize transport rates"*).
1.  **Automated Subgroup Discovery:** An LLM iteratively generates SQL `GROUP BY` and `WHERE` clauses to segment the connected dataset. 
2.  **Greedy Measurement:** The system executes these queries against read-only replicas to find segments that yield a positive delta against the objective (e.g., `HomePlanet = 'Mars'`).
3.  **Graph Write:** The results are written to the global graph as **Observational Edges**. These represent *conditional probability* ($P(\text{Outcome} | \text{Condition})$) rather than strict causality.
*   *Constraint:* This evaluation process must run asynchronously; it does not need to block the UI in real-time.

### Phase 2: The Sleep Cycle (State-Space Search & Global Optimization)
During offline background processing, the system compensates for the myopic, greedy nature of the Phase 1 LLM.
1.  **Monte Carlo Tree Search (MCTS):** Background workers run MCTS against the messy graph of SQL segments generated during the day. The algorithm simulates thousands of rollouts, discovering combinations of features (macro-segments) that yield higher global objective scores than any single segment found by the LLM.
2.  **Ontological Abstraction:** The offline LLM evaluates the optimal multi-step paths generated by the MCTS and generates a domain-agnostic heuristic rule.
3.  **Graph Write:** The abstracted rule is injected back into the graph as a `[Meta-Heuristic]` node.

## 3. Ontological Naming & Cross-Domain Portability

To prevent the "Cold Start" problem when an analyst connects a completely new, unrelated dataset, the abstraction process must strip away all domain-specific payloads. 

*   **The Mechanism:** The Sleep Cycle LLM maps specific variables to a universal, high-level structural ontology before saving the heuristic.
*   **Example Translation:** 
    *   *Raw MCTS Output:* `[Location: Mars] + [Economic Status: High]` $\rightarrow$ `(+20% Transport Rate)`
    *   *Ontological Translation:* `Mars` $\rightarrow$ `[Primary Population Center]`; `Transport Rate` $\rightarrow$ `[System Output]`
    *   *Final `[Meta-Heuristic]` Node:* *"High economic status originating from primary population centers is the strongest predictor of positive objective outcomes."*
*   **Actionability:** When a new dataset (e.g., B2B SaaS Churn) is connected, the Phase 1 LLM queries the `[Meta-Heuristic]` nodes. It inherits this abstract rule and instantly knows to write its first exploratory SQL queries segmenting by `[Company HQ Location]` and `[Revenue]`, bypassing random guessing.

## 4. Graph Schema Definitions (V1 to V2 Compatible)

To ensure V1 data remains mathematically compatible with V2, the graph schema must strictly track the epistemological source of the edge weight.

### Nodes
*   **`State_Segment`:** A defined slice of observational data (e.g., a specific SQL `WHERE` clause outcome).
*   **`Intervention`:** A physically executable action (Reserved for V2).
*   **`Outcome`:** The measured objective metric.
*   **`Meta-Heuristic`:** Ontologically abstracted principles generated during the Sleep Cycle.

### Edges
*   **`OBSERVED_CORRELATION`** (State $\rightarrow$ Outcome): Written by V1. Represents conditional probability. The MCTS utilizes these to find predictive paths.
*   **`PRODUCED_EFFECT`** (Intervention $\rightarrow$ Outcome): Written by V2. Represents empirically validated causality ($do$-calculus). The MCTS will heavily prioritize these over observed correlations.

## 5. V2 Roadmap: The Dual-Engine Episodic Layer

V2 upgrades the architecture from an Observational Engine to an Active Reinforcement Learning Agent by introducing physical sandbox execution. 

### The Control Plane Router
The front-end analyst input is intercepted by a routing agent that directs the evaluation to one of two async execution tracks based on user intent:

#### Engine A: Observational SQL (The Fast Track)
*   **Function:** Retains the V1 exploratory data analysis.
*   **Use Case:** Rapid discovery, finding predictive cohorts, and populating the graph with conditional probabilities.

#### Engine B: State-Search Experimental Sandbox (The Verification Track)
*   **Function:** Executes isolated, physical interventions (e.g., code changes, config updates) in ephemeral containerized environments.
*   **Mechanism:** Uses **A* Search** (guided by `[Meta-Heuristic]` nodes as the heuristic function $h(s)$) to evaluate the existing graph and determine the highest-probability path to test *before* spinning up the expensive sandbox.
*   **Use Case:** Proving true causality. It answers the analyst's prompt: *"Verify if enforcing this constraint physically causes the lift, or if it is just correlated."*

### V2 Sleep Cycle Impact
With both engines running, the Phase 2 MCTS logic is updated to traverse a mixed graph. It relies on the dense web of `OBSERVED_CORRELATION` edges for rapid exploration, but its scoring function applies a massive multiplier to paths validated by `PRODUCED_EFFECT` edges, ensuring the offline LLM generates heuristics anchored in proven causality rather than just correlation.
