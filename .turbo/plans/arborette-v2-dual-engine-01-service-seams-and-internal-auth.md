# Plan: Service Seams & Internal Auth

## Context

V2 adds a fourth service (the Verifier) that would otherwise become the third copy-paste consumer of duplicated HTTP plumbing, and a second internal audit writer against an unauthenticated endpoint. This plan consolidates the seams first — the spec explicitly requires R31 to land before the Verifier consumes them — and establishes the service-to-service shared-secret contract every later internal surface (audit writes, worker serve endpoints, sandbox) reuses. It also lands the batched Meta-Heuristic fetch (R23) so the read path the Verifier's heuristic function later hammers is no longer N+1, and anchors the bare `orchestrator` line in `.gitignore` that breaks search and staging in exactly the directories this project touches most.

Spec requirements covered: R23 (batched `GetMetaHeuristics`), R27 (authenticated internal write surfaces — this plan lands the middleware and `POST /internal/audit`; the workers' serve endpoints adopt the same middleware in a later shell), R31 (seam consolidation before the Verifier lands).

## Pattern Survey

### Analogous Features
- `internal/orchestrator/server.go:225-238` — `errorResponse` struct + `writeJSON`/`writeErr` helpers; identical to the sandbox pair except the log prefix (`"orchestrator: encode response"`). These are the JSON writer/error helpers step 1 consolidates.
- `internal/sandbox/server.go:291-305` — the twin `errorResponse`/`writeJSON`/`writeErr` (log prefix `"sandbox:"`). Byte-for-byte duplicate of the orchestrator copy — the extraction target.
- `internal/auditclient/client.go:24-80` — orchestrator HTTP client #1: `AuditError{Message}` typed error, `Client{baseURL, client}`, `NewClient(baseURL, *http.Client)` with nil→`defaultTimeout` (30s), POSTs JSON to `/internal/audit`, decodes `{"error":...}` on non-201.
- `internal/mcpserver/orchestratorclient.go:24-98` — orchestrator HTTP client #2: `OrchestratorError{Message}`, `OrchestratorClient{baseURL, client}`, `NewOrchestratorClient` with nil→`defaultOrchestratorTimeout` (2m), POSTs multipart to `/goals`, same `{"error":...}` decode. It sends multipart, auditclient sends JSON, and their timeouts differ (30s vs 2m) — the unified timeout config must accommodate both.
- `internal/sandboxclient/client.go:180-210` — `(*Client).post(ctx, path, in, out)`: the most complete request/decode/typed-error helper already extracted (marshal → POST → non-200 → `SandboxError{Status, Message}` with `{"error"}` fallback → decode). Closest prior art for the unified client body; `SandboxError` even carries `Status`, which the two orchestrator errors do not.
- `internal/service/auth.go:27` — `BearerAuth(token, next)`: existing config-driven shared-secret HTTP middleware (SHA-256 + constant-time compare, `WWW-Authenticate` challenge, fail-open on empty token with a warning log). Currently the only middleware; applied once, at `cmd/mcpserver/main.go:63`.
- `internal/orchestrator/server.go:205` — `mux.HandleFunc("POST /internal/audit", s.handleAudit)`: the unauthenticated internal endpoint to guard. `handleAudit` (`internal/orchestrator/audit.go:43`) already does MaxBytesReader + `writeErr`. `Routes()` returns a bare `http.NewServeMux()` — no middleware chain exists yet, so wrapping is per-route or whole-mux.
- `internal/sleepcycle/worker.go:83-95` — `searchRepo`, the existing narrow consumer interface that already declares `ListEligibleFindings`/`MarkStaleMetaHeuristics` (plus write methods). The worker already does NOT depend on `graph.Repository`.

### Reusable Utilities
- `internal/service/{httpserver.go,shutdown.go,auth.go}` — the target package already exists with `RunHTTPServer`, `WaitForShutdown`, `BearerAuth`. Both `cmd/orchestrator/main.go:88` and `cmd/sandbox/main.go` already call `service.RunHTTPServer(name, addr, Routes())`. Adding `writeJSON`/`writeErr` here follows the established home for service-agnostic HTTP plumbing.
- `internal/heuristics/service.go:41-44` — `heuristicRepo` interface (`GetMetaHeuristic`, `TraceCausalChain`); `service.go:82` loops `GetMetaHeuristic` per id inside `Query` — the exact N+1 to replace. `Query` skips `graph.ErrNotFound` per-id (orphan retirement via `retireOrphans`); the batch method must preserve the ability to detect which ids were missing. Fake at `internal/heuristics/heuristics_test.go:158-177` returns wrapped `ErrNotFound` per id.
- `internal/graph/neo4j.go:163-169` — singular `GetMetaHeuristic` via `getNode` (MATCH by `{id: $id}`). The batch version MATCHes over an id list (`WHERE n.id IN $ids`).
- `internal/domain` — dependency-free types (`MetaHeuristic`, etc.) all clients/DTOs are typed from; the CGO-free boundary documented at `internal/sandboxclient/client.go:1-11` constrains where a unified client may live.

### Convention Anchors
- Infra-constructor convention: every client is `NewX(baseURL string, httpClient *http.Client)` with `nil → &http.Client{Timeout: defaultX}`. A unified client must keep this signature shape.
- Typed-error-vs-masked split: clients return a typed error carrying the server's `{"error"}` body (caller-safe) and plain `fmt.Errorf` for transport/marshal/decode faults (which leak internal addresses and are masked by the caller). Documented explicitly at `internal/mcpserver/orchestratorclient.go:24-29`. The unified single typed error must preserve this distinction.
- Consumer-defined narrow interfaces: `heuristics` (`service.go:36-44`), `sleepcycle` (`worker.go:78-104`), and orchestrator's own `goalStore`/`sandboxExecutor` all declare narrow interfaces at the call site; `graph.Repository`'s own doc comment (`repository.go:41-46`) says "prefer a narrow contract at a new call site over widening this." The narrowing step is the doc-sanctioned direction. The cost is concrete: orchestrator's `fakeRepo` (`server_test.go:502-507`) stubs `ListEligibleFindings`/`MarkStaleMetaHeuristics` it never calls.
- Alias-removal target: `internal/orchestrator/sandboxclient.go` re-exports `sandboxclient` types via `type X = sandboxclient.X` and `var NewSandboxClient = sandboxclient.NewClient` (line 26). `NewSandboxClient` has exactly 3 call sites — `cmd/orchestrator/main.go:67`, `internal/orchestrator/sandboxclient_test.go:19` and `:37`. The two tests (`TestPostDecodesSandboxErrorBody`, `TestPostFallsBackWhenBodyEmpty`) exercise the `sandboxclient.post` error path; `internal/sandboxclient/` currently has no `_test.go` file. The type aliases at lines 11-23 are used widely across orchestrator and are not in scope to remove.
- Config-as-plain-struct + env-load: secrets have no defaults (`os.Getenv`), non-secrets use `env(key, default)` (`internal/config/config.go:222-229`). A new internal shared-secret follows `MCP.AuthorizationToken` (`config.go:123,280`: `os.Getenv`, empty disables). It must live on both the writer side (`OrchestratorConfig`) and the sender side (`SleepCycleConfig`, since the worker's audit client at `cmd/sleepcycle/main.go:68` is the one client that must send it).
- Worker audit seam: worker depends on `auditAppender` (`worker.go:115-116`, one method `Append`); the header is added in the client's request build, not the interface.
- `.gitignore` last line is bare `orchestrator` (no slash); `/out/` and `*.exe` show the anchored form matches existing style.

### Proposed Alignment
This shell is consolidation, and the idioms are already established. Put `writeJSON`/`writeErr` in `internal/service` beside `BearerAuth`/`RunHTTPServer`. Build the unified orchestrator client on the `sandboxclient.post` shape (typed error carrying `Status`); reconcile JSON-vs-multipart bodies and 30s-vs-2m timeouts by keeping the universal `NewClient(baseURL, *http.Client)` signature and letting each caller inject its own timeout. Reuse `BearerAuth` for internal auth rather than inventing a parallel middleware; wire it per-route in `Routes()` and thread the secret through both `OrchestratorConfig` (verify) and `SleepCycleConfig` (send). Remove `ListEligibleFindings`/`MarkStaleMetaHeuristics` from `graph.Repository` (only `sleepcycle.searchRepo` consumes them, and it already redeclares them locally).

## Implementation Steps

1. **Extract shared JSON writer/error helpers into `internal/service`**
   - Add `internal/service/json.go` with exported `WriteJSON(w http.ResponseWriter, status int, v any)` and `WriteErr(w http.ResponseWriter, status int, msg string)` plus the `errorResponse` shape, generalized from `internal/orchestrator/server.go:225-238`. Keep the encode-failure log line; use a service-neutral prefix (e.g. `"service: encode response"`) since the caller identity was the only difference between the two copies.
   - Add `internal/service/json_test.go` covering success encode, error envelope shape (`{"error": msg}`), and Content-Type header.
   - Replace the local `writeJSON`/`writeErr`/`errorResponse` with direct calls to `service.WriteJSON`/`service.WriteErr` at every call site. The definitions live in `internal/orchestrator/server.go` and `internal/sandbox/server.go`, but the orchestrator call sites span the whole package (~67 calls across 9 files): `submit.go` (22), `verification.go` (24), `chat.go` (5), `heuristics.go` (5), `hypothesis.go` (2), `sleepcycle.go` (2), `stream.go` (1), `audit.go` (3), `server.go` (3). The edits are mechanical find-replace. Do not keep thin local wrappers — direct calls keep the duplication permanently removed and the verification grep meaningful.

2. **Unify the orchestrator HTTP clients**
   - Create `internal/orchestratorclient/client.go`: one `Client{baseURL, client, authToken}` with `NewClient(baseURL string, httpClient *http.Client) *Client` (nil → 30s default, matching the audit default) and a `WithAuthToken(token string)`-style setter or constructor variant for the internal-auth secret (step 6). Model the request/decode/error body on `internal/sandboxclient/client.go:180-210`.
   - Single typed error `OrchestratorError{Status int, Message string}` carrying the server's `{"error"}` body; transport/marshal/decode faults stay plain `fmt.Errorf` per the documented split at `internal/mcpserver/orchestratorclient.go:24-29`.
   - Port `Append` (JSON POST `/internal/audit`, expects 201) from `internal/auditclient/client.go` and `SubmitGoal` (multipart POST `/goals`) from `internal/mcpserver/orchestratorclient.go` as methods on the one client. Keep the exact name and signature `SubmitGoal(ctx context.Context, goal, importPath string) (string, error)` — the `goalSubmitter` interface at `internal/mcpserver/tools.go:41-42` requires it, and `sleepcycle.auditAppender` requires `Append` unchanged; with those names both consumer interfaces are satisfied without edits. Timeouts: callers inject their own `*http.Client` — `cmd/mcpserver/main.go` passes a 2m-timeout client (preserving `defaultOrchestratorTimeout`), `cmd/sleepcycle/main.go` passes nil (30s default).
   - Migrate consumers: `cmd/sleepcycle/main.go:68` and the `mcpserver` tool wiring construct `orchestratorclient.NewClient`. Update the `*OrchestratorError` references that live outside the deleted file to the new package: `internal/mcpserver/tools.go:184` (`var oerr *OrchestratorError` in the `errors.As` unwrap; add the `orchestratorclient` import) and `internal/mcpserver/tools_test.go:265,284` (fake constructs `&OrchestratorError{...}`); the doc comment at `tools.go:139` also names the type. Port `internal/auditclient/client_test.go` and `internal/mcpserver/orchestratorclient_test.go` into `internal/orchestratorclient/client_test.go` — rewriting the ported tests' own type references to the unified error (`client_test.go:73` does `var ae *AuditError`; it becomes `*OrchestratorError`) — then delete `internal/auditclient/` and `internal/mcpserver/orchestratorclient.go`.

3. **Remove the `NewSandboxClient` alias var; give `sandboxclient` its own tests**
   - Delete `var NewSandboxClient = sandboxclient.NewClient` at `internal/orchestrator/sandboxclient.go:26`; keep the type aliases at lines 11-23 (widely used, out of scope).
   - Update `cmd/orchestrator/main.go:67` to call `sandboxclient.NewClient` directly.
   - Move `TestPostDecodesSandboxErrorBody` and `TestPostFallsBackWhenBodyEmpty` from `internal/orchestrator/sandboxclient_test.go` into a new `internal/sandboxclient/client_test.go` (package `sandboxclient` or `sandboxclient_test`); delete the orchestrator copy.

4. **Narrow the graph interface for Sleep-Cycle-only methods**
   - Remove `ListEligibleFindings` and `MarkStaleMetaHeuristics` from `graph.Repository` (`internal/graph/repository.go:94-105`); keep them as concrete methods on the Neo4j implementation.
   - `internal/sleepcycle/worker.go:83-95` (`searchRepo`) already declares both — no change needed there; verify the concrete repo still satisfies `searchRepo` at the `cmd/sleepcycle` wiring site.
   - Drop the now-dead stubs from orchestrator's `fakeRepo` (`internal/orchestrator/server_test.go:502-507`) and any other `graph.Repository` fakes (check `internal/testutil`).

5. **Add batched `GetMetaHeuristics` and use it in `heuristics.Query`**
   - Add `GetMetaHeuristics(ctx context.Context, ids []string) ([]domain.MetaHeuristic, error)` as a concrete method on the Neo4j repository in `internal/graph/neo4j.go` and to the narrow `heuristicRepo` interface (`internal/heuristics/service.go:41-44`) — do **not** add it to the shared `graph.Repository` interface. Widening `graph.Repository` would force `fakeRepo` and every other full-interface fake to stub a method they never call, exactly the dead-stub cost step 4 removes (`repository.go:41-46`: "prefer a narrow contract at a new call site over widening this"). Both wiring sites pass the concrete `*graph.Neo4jRepository`, which satisfies the widened `heuristicRepo` directly.
   - Implement with a single `MATCH (n:MetaHeuristic) WHERE n.id IN $ids` query (empty `ids` → empty result, no session). Missing ids are simply absent from the result — not an error. Result order from Neo4j is arbitrary.
   - Extend `internal/graph/graph_test.go` (or `sleepcycle_test.go` harness) with a batch-fetch test: seed several Meta-Heuristics, fetch a mix of present and absent ids, assert only present ones return.
   - Update `heuristics.Query` (`internal/heuristics/service.go:82`): replace the per-id `GetMetaHeuristic` loop with one `GetMetaHeuristics` call over the similarity-hit ids, then **re-assemble matches by iterating the input `ids` slice in order** against a map of returned Meta-Heuristics keyed by id — `Match` is contractually "ordered by similarity" (`service.go:24`) and `SimilaritySearch` returns ids in cosine-distance rank order (`internal/store/embeddingstore.go:73`), so iterating the batch result directly would silently destroy the ranking. Ids absent from the map form the missing-id set for `retireOrphans`, preserving its behavior. Update the fake in `internal/heuristics/heuristics_test.go:158-177`; keep an orphan-retirement test proving absent ids still get retired, and add an ordering test where the fake returns Meta-Heuristics in reversed order and `Query` still yields similarity order.

6. **Shared-secret internal-auth middleware on `POST /internal/audit`**
   - Add `InternalAuthToken` to `OrchestratorConfig` and `SleepCycleConfig` in `internal/config/config.go`, loaded via bare `os.Getenv` (secret — no default; empty disables, matching `MCP.AuthorizationToken` at `config.go:123,280`). Both fields read the **same single env var** (suggested: `INTERNAL_AUTH_TOKEN`, adjusted to the file's naming scheme) — it is one shared secret, and splitting it across two must-match variables invites silent divergence: on mismatch the orchestrator 401s and `worker.report` (`internal/sleepcycle/worker.go:416-422`) logs-and-swallows every audit failure, so the run "succeeds" while its audit trail (including the `sleepcycle_run_complete` detail that carries Phase-2 winners) silently vanishes. Document that failure mode in a comment beside the config fields.
   - Reuse `service.BearerAuth` (`internal/service/auth.go:27`) as the guard: add an internal-auth-token field to `Server` (set via `NewServer`) and read it inside `Routes()` — this avoids changing the `Routes()` signature and its callers — wrapping only the internal route: `mux.Handle("POST /internal/audit", service.BearerAuth(s.internalAuthToken, http.HandlerFunc(s.handleAudit)))`. `NewServer` gains one parameter, which compile-breaks its five call sites: `cmd/orchestrator/main.go:79` (pass the config token) plus the four test constructions `internal/orchestrator/handlers_more_test.go:94` and `internal/orchestrator/server_test.go:593,841,864` (pass `""` — fail-open keeps existing tests green). Analyst-facing routes stay unguarded (analyst auth is explicitly deferred). The fail-open-on-empty behavior with warning log is the intended dev-mode default.
   - Sender side: the unified client from step 2 sets `Authorization: Bearer <token>` on requests when its configured token is non-empty; `cmd/sleepcycle/main.go` passes `cfg.SleepCycle.InternalAuthToken`; `cmd/orchestrator/main.go` passes `cfg.Orchestrator.InternalAuthToken` into server construction. Update `docker-compose`/`.env.example` if they enumerate service env vars.
   - Tests: orchestrator server test proving `POST /internal/audit` returns 401 without/with-wrong header when a token is configured and succeeds with the right one; client test proving the header is attached. This middleware is the stable seam the later worker serve endpoints (R24/R27) and Verifier shells reuse — keep it config-driven and route-scoped.

7. **Anchor the `.gitignore` entry**
   - Change the bare `orchestrator` line (last line of `.gitignore`) to `/orchestrator` so it only ignores the root build artifact, not `internal/orchestrator`/`cmd/orchestrator`. Verify with `--no-index` — plain `git check-ignore` on a tracked file like `server.go` exits 1 both before and after the fix (the index exempts tracked files), so it proves nothing. Working check: `git check-ignore --no-index internal/orchestrator/server.go` matches `.gitignore:24` before the fix and must report nothing (exit 1) after; `git check-ignore --no-index orchestrator` must still match.

## Verification

- `go build ./... && go vet ./...` — clean compile after the package moves/deletions.
- `go test ./...` — full suite; specifically expect green in `internal/service`, `internal/orchestratorclient`, `internal/sandboxclient` (new tests exist), `internal/heuristics`, `internal/graph`, `internal/orchestrator`, `internal/sleepcycle`, `internal/mcpserver`.
- Duplication gone: `grep -rn "func writeJSON" internal/` returns only `internal/service` (use plain `grep -r`, not gitignore-respecting tools, until step 7 lands).
- Package deletions took: `internal/auditclient` and `internal/mcpserver/orchestratorclient.go` no longer exist; `grep -rn "auditclient" internal cmd` returns nothing.
- Internal auth smoke (with `make up` stack or httptest): with token configured, `curl -s -o /dev/null -w '%{http_code}' -X POST localhost:8080/internal/audit -d '{}'` → `401`; same request with `Authorization: Bearer <token>` → `201` (valid body) — and the Sleep-Cycle worker's audit writes still land in `audit_log` end-to-end.
- N+1 gone: `heuristics.Query` makes exactly one graph call for Meta-Heuristic hydration (assert via the test fake's call counter); results stay in similarity order even when the fake returns them shuffled; orphan retirement still fires for missing ids.
- Gitignore: `git check-ignore --no-index internal/orchestrator/server.go` exits 1 (before the fix it matches `.gitignore:24`); `git add internal/orchestrator` no longer warns; `git check-ignore --no-index orchestrator` still matches the root binary.
- Edge cases to spot-check: `GetMetaHeuristics` with empty id slice (no session, empty result); unified client with nil `http.Client` (30s default applies); auth middleware with empty token (fail-open warning, request passes — dev mode); multipart `SubmitGoal` still round-trips file upload against a live orchestrator.
