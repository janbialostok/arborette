# Plan: Agent Chat Backend

## Context

The pipeline's output doesn't have to stop at a queryable graph — an analyst can preview a working, conversational agent built on it. That agent is a standard Claude tool-use agent scoped to the two read-only MCP tools, connected via Claude's native MCP connector rather than a hand-written tool-use loop. The connector is a server-side Anthropic API feature: Anthropic's own infrastructure opens the connection to the MCP Server URL, so the URL must be publicly reachable (not in-network) and the Anthropic API key must be held by a backend, never the browser. This shell builds that backend piece — the Orchestrator's chat endpoint and the MCP Server's public exposure — which the preview/chat UI (Shell 10) streams against.

Covers R21 and the backend half of R23; R24 (production export) is deferred past the MVP, but its future packaging target was decided by the analyst during plan expansion: a **downloadable zip** the analyst runs locally. (The spec's Open Questions section still lists the format as open — that entry predates this decision, and this workflow never edits the spec; the decision here supersedes it.) This plan therefore keeps every new configuration seam primitive-valued and env-injected (constructors take plain strings, `config.Load` reads env), so a bundled backend can later wire the same constructors from file-based config without an interface change. `submit_analyst_goal` is deliberately excluded from the chat agent's tool set (spec R21 acceptance): it is a write action with no chat-surface confirmation flow.

**Plan risk (dev-loop friction, not a blocker):** the native MCP connector means Anthropic's infrastructure dials the MCP Server, so a fully-live local chat round trip requires tunneling the MCP port (e.g. `cloudflared`/`ngrok`, spec § Local dev). Unit and handler tests fake the Anthropic side entirely; only the optional live smoke needs a tunnel and a real API key.

## Pattern Survey

### Analogous Features
- `internal/llm/client.go:54` — `NewClient` / the whole package is the **only** Anthropic SDK wrapper in the repo. It calls the *non-beta* `sdk.Messages.New` (structured output, `completeWithContent` at :418) — synchronous, non-streaming. The chat endpoint needs a different seam: **streaming** + the **beta** Messages API (the MCP connector lives only on `client.Beta.Messages`), so this is the closest prior art but not directly reusable for streaming/MCP.
- `internal/orchestrator/stream.go:14` — `handleStream`: the SSE-to-browser pattern (sets `text/event-stream`/`Cache-Control: no-cache`/`Connection: keep-alive`, asserts `http.Flusher`, writes `data: %s\n\n` frames + `flusher.Flush()`). The chat endpoint mirrors this frame-writing shape but streams per-request tokens rather than hub events.
- `internal/orchestrator/hub.go:25` — `Hub`: in-memory pub/sub keyed by `optimization_function_id` with a replay ring buffer. Built for the async trigger→subscribe race of the long loop; a per-message chat request/response streams directly and does **not** need the hub.
- `internal/orchestrator/submit.go:47`/`:84` — `handleSubmitGoal` calls `s.claude.GenerateEvaluationMatrix` inline inside a request handler and maps a Claude fault to `502` — the analog for a synchronous handler that drives a Claude call.
- `internal/mcpserver/tools.go:112` — `RegisterTools` registers exactly the two read-only tools the chat agent scopes to (`get_optimized_heuristics`, `trace_causal_chain`) plus `submit_analyst_goal`.
- `cmd/mcpserver/main.go:52-58` — MCP server construction: `mcp.NewServer` + `mcp.NewStreamableHTTPHandler`, wrapped by `service.RunHTTPServer`. The comment at `:55-57` names this line as the intended wrap point for bearer-token middleware. No auth middleware exists yet anywhere in the repo.
- `web/lib/proxy.ts:90` — `forwardStream`: the Next.js BFF SSE proxy (undici `Agent{bodyTimeout:0,headersTimeout:0}`, `x-accel-buffering: no`) that Shell 10's chat UI will mirror to stream the new chat endpoint; `web/app/api/orchestrator/goals/[id]/stream/route.ts` is the thin route wrapper to copy.
- `internal/mcpserver/orchestratorclient.go:34` — `OrchestratorClient`: an outbound HTTP client with timeout + analyst-safe error masking (`OrchestratorError`), the model for any client attaching an `Authorization` header.

### Reusable Utilities
- `internal/service/httpserver.go:27` — `RunHTTPServer(name, addr, handler)` — shared graceful-shutdown HTTP runner; bearer-auth middleware is just an `http.Handler` decorator passed into it.
- `internal/config/config.go:136` `AnthropicConfig` (`APIKey` secret w/ no default, `Model` overridable) and `:106` `MCPConfig` (`Port`, `OrchestratorURL`) — the new chat-model, MCP `authorization_token`, and public-MCP-URL fields slot in here. Env helpers `env`/`intEnv`/`boolEnv` at `:255+`.
- `anthropic-sdk-go@v1.58.0` `beta.go:76` — `AnthropicBetaMCPClient2025_11_20 = "mcp-client-2025-11-20"` — the exact beta constant the spec names, already vendored.
- `anthropic-sdk-go` `betamessage.go:95` — `BetaMessageService.NewStreaming(ctx, BetaMessageNewParams, opts...)` — the streaming + MCP-connector call path. Connector params: `BetaRequestMCPServerURLDefinitionParam{Name, URL, AuthorizationToken, ToolConfiguration}` (`betamessage.go:7352`) with `BetaRequestMCPServerToolConfigurationParam{Enabled, AllowedTools}` (`:7337`), and the `mcp_toolset` tool entry via `BetaToolUnionParamOfMCPToolset(serverName)` (`:10256`) / `BetaMCPToolsetParam` (`:5466`).
- `internal/llm/client.go:40` — `messagesClient` one-method interface (injected fake) — the testability pattern to replicate for the streaming/beta chat client so tests need no API key.
- `internal/orchestrator/server.go:176-186` — `writeJSON`/`writeErr`/`errorResponse`; `stream.go:47` `writeEvent` — response + SSE-frame helpers.
- `internal/orchestrator/server.go:158` — `lookupGoal(ctx,w,id)` and the `goalStore` interface (`:64`, `Get`/`List`) — the existing seam for binding a chat session to the active goal (`store.Goal` carries `GoalText`, `EvaluationMatrix`, `DataSourceRef`); `goal_registry` is the persistence table.
- `internal/orchestrator/audit.go:18` — `recordAudit(ctx, action, eventType, detail)` — single audit-write path if chat activity is later audited (not in this shell's scope).

### Convention Anchors
- **Consumer-defined narrow interfaces**: `Server` depends on `claudeClient`, `sandboxExecutor`, `goalStore`, etc. defined in `server.go:47-90`; concretes wired in `cmd/orchestrator/main.go`. The chat/streaming-Claude collaborator is a new narrow interface field on `Server` (extend `NewServer`), not a concrete import.
- **Infra-constructor**: `NewClient(apiKey, model)`, `NewOrchestratorClient(baseURL, httpClient)` take primitives; wiring lives in `cmd/*/main.go` from `config.Load()`. Secrets (`ANTHROPIC_API_KEY`) have no env default and fail at use.
- **Error masking**: handlers log internal errors and return generic messages (`writeErr(...,"internal error")`); only vetted messages surface verbatim. `tools.go:128-133` documents the MCP SDK copies returned error text verbatim to the caller — applies to any new error path.
- **SSE frame contract**: `data: <json>\n\n`, **no `event:` line**; clients discriminate on a top-level `type` field (`web/lib/orchestrator.ts:14` `OrchestratorEvent` union, `hub.go:14` `Event{Type,Payload}`). The chat stream keeps this JSON-type-discriminated framing.
- **SDK test fakes** (`internal/llm/client_test.go:35`): canned `*anthropic.Message` built by `json.Marshal`→`json.Unmarshal`, injected via the one-method interface — no network, no key. Streaming tests follow the same spirit (see Verification: httptest-backed SSE fake).
- **Route registration**: `net/http` `ServeMux` with method-prefixed patterns in `Server.Routes()` (`server.go:143`), e.g. `mux.HandleFunc("POST /goals/{id}/chat", ...)`.
- **`http.Handler` middleware wrap point**: services compose a single `http.Handler` and hand it to `service.RunHTTPServer`; MCP bearer auth belongs as a decorator at `cmd/mcpserver/main.go:58`.
- **docker-compose exposure**: `mcpserver` publishes `:8082` with `env_file: [.env]` + `x-app-environment` overrides (`docker-compose.yml:190-209`); tunnel config for live preview testing slots in as documentation, not a new always-on service.

### Proposed Alignment
Blend, don't extend in place. The MCP-server bearer-auth piece follows existing conventions cleanly: an `http.Handler` decorator inserted at the documented `cmd/mcpserver/main.go:58` wrap point, token read via a new `MCPConfig.AuthorizationToken` env field. The chat client deviates from the one existing Anthropic seam (`internal/llm`'s non-streaming structured-output `Client`) deliberately: chat needs `client.Beta.Messages.NewStreaming` with `mcp_servers`/`mcp_toolset` and the `mcp-client-2025-11-20` beta header — a distinct constructor and narrow `Server` collaborator interface with its own streaming test fake. Browser-facing streaming follows the established SSE contract (`stream.go` frame writing; Shell 10 mirrors `web/lib/proxy.ts`'s `forwardStream`); session binding goes through the existing `goalStore`/`lookupGoal` seam (session-level, no query-time filter in the single-dataset MVP).

## Implementation Steps

1. **Config plumbing** (`internal/config/config.go`, `.env.example`)
   - Add `AnthropicConfig.ChatModel` — env `ANTHROPIC_CHAT_MODEL`, default `claude-sonnet-5` (spec § Tech Stack: Sonnet for the interactive chat surface vs. Opus for analytical Phase 1/2 work; the existing `Model` field stays the structured-output model).
   - Add `MCPConfig.AuthorizationToken` — env `MCP_AUTHORIZATION_TOKEN`, secret with no default (matches the secrets convention: unset loads empty, consumer decides).
   - Add `MCPConfig.PublicURL` — env `MCP_PUBLIC_URL`, no default. This is the publicly-reachable address Anthropic's connector dials (tunnel URL in dev, public AWS endpoint in production) — deliberately distinct from the in-compose `http://mcpserver:8082` hostname, which the connector cannot reach.
   - Document all three in `.env.example` with a comment explaining `MCP_PUBLIC_URL` must be publicly reachable and that live chat preview in dev requires a tunnel.
2. **MCP Server bearer-token middleware** (`internal/service/auth.go` + test, `cmd/mcpserver/main.go`)
   - New `service.BearerAuth(token string, next http.Handler) http.Handler`: rejects requests whose `Authorization` header is not `Bearer <token>` with `401` and a minimal JSON body; compares with `crypto/subtle.ConstantTimeCompare`. Lives in `internal/service` beside `RunHTTPServer` since it is service-agnostic HTTP plumbing.
   - Empty configured token = auth disabled: log a prominent warning and serve unwrapped. This keeps local `make up` / existing E2E flows working without minting a token; public deployments set the token. Fail-open is acceptable **only while the port stays host-local** — tunneling `:8082` (the live-preview instruction below) publishes exactly this listener, so the warning log line must say so explicitly (e.g. "MCP auth disabled — do NOT tunnel or publicly expose :8082 in this state"), and the chat client's `configured` predicate (Step 3) refuses to drive the connector at an untokened endpoint, so a working preview cannot silently ride on an unauthenticated public MCP server.
   - **Scheme assumption (verify at live smoke):** the middleware accepts exactly `Authorization: Bearer <token>`, and the plan assumes Anthropic's connector transmits `mcp_servers[].authorization_token` in that form (the MCP standard). If the live smoke 401s despite a correct token, diagnose a scheme mismatch (raw token vs. `Bearer ` prefix) before suspecting the token value.
   - Wrap at the documented wrap point (`cmd/mcpserver/main.go:58`): `handler := service.BearerAuth(cfg.MCP.AuthorizationToken, mcp.NewStreamableHTTPHandler(...))` — tool handlers and transport untouched, per the comment at `:55-57`.
   - Add a short "public exposure / tunnel" note to `docker-compose.yml`'s `mcpserver` service (comment only): `cloudflared tunnel --url http://localhost:8082` (or ngrok) for live preview testing, per spec § Local dev — **with the warning that `MCP_AUTHORIZATION_TOKEN` must be set before tunneling** (a tunnel publishes the fail-open dev listener; see the middleware bullet above).
3. **Streaming chat client** (`internal/llm/chat.go` + `chat_test.go`)
   - New `ChatClient` distinct from the structured-output `Client`, constructor `NewChatClient(apiKey, model, mcpURL, mcpToken string) *ChatClient` (infra-constructor convention; primitives keep the future zip-export wiring file-config-friendly).
   - Exported request/event types: `ChatMessage{Role, Content string}` and `ChatEvent{Type string, ...}` with event types `text` (delta text), `tool_use` (MCP tool invocation started: tool name), `tool_result` (tool round-trip finished), `done`, `error` — the minimal set Shell 10's UI needs to render assistant text and "consulting the graph…" affordances.
   - Method `Chat(ctx context.Context, system string, msgs []ChatMessage, emit func(ChatEvent) error) error`: builds `BetaMessageNewParams` with `Model` (from config), **`MaxTokens: chatMaxTokens`** (new package const, e.g. `8192` — `MaxTokens` is `api:"required"` and always marshaled; leaving it zero sends `"max_tokens":0`, which the API treats as "populate the prompt cache without generating a response", i.e. a silently empty chat — mirror the existing `maxTokens` const at `client.go:34-36`), `System`, converted `Messages`, `Betas: []anthropic.AnthropicBeta{anthropic.AnthropicBetaMCPClient2025_11_20}`, `MCPServers: []anthropic.BetaRequestMCPServerURLDefinitionParam{{Name: "arborette", URL: mcpURL, AuthorizationToken: anthropic.String(mcpToken), ToolConfiguration: {AllowedTools: []string{"get_optimized_heuristics", "trace_causal_chain"}}}}`, and `Tools: []anthropic.BetaToolUnionParam{anthropic.BetaToolUnionParamOfMCPToolset("arborette")}` — scoping enforced server-side by `allowed_tools` (R21: `submit_analyst_goal` excluded), with the `mcp_toolset` entry activating the connector tool group.
   - Calls `client.Beta.Messages.NewStreaming`, iterates the `ssestream` events, and translates `content_block_delta` text deltas / `mcp_tool_use` block starts / `mcp_tool_result` blocks / `message_stop` into the `ChatEvent` domain types via `emit`. Track the `stop_reason` from `message_delta` (`BetaRawMessageDeltaEventDelta.StopReason` — the *only* stream event that carries it). The invariant: **every stream ends with exactly one terminal `ChatEvent` (`done` or `error`), whatever the stop reason.** Dispositions: `end_turn`/`stop_sequence`/`max_tokens`/`tool_use` → `done`; `pause_turn` (the API paused a long-running server-side connector turn, expecting the partial assistant turn to be resubmitted) → either resume by resubmitting per the SDK's documented contract or emit `error` — never a bare `done`, which would silently truncate mid-tool; `refusal` → `error` (vetted "the agent declined to answer" message); any other/unknown reason (`compaction`, `model_context_window_exceeded`, future additions) → `done` as the default arm, so a new stop reason can never leave Shell 10's UI hanging without a terminal frame. Callback style keeps the orchestrator-side fake trivial (no ssestream construction in orchestrator tests).
   - Disabled state lives in the client, not in a nil interface: `NewChatClient` records `configured := apiKey != "" && mcpURL != "" && mcpToken != ""` — the token is part of the predicate deliberately: a tunnel publishes the MCP Server's fail-open dev listener (Step 2), so the orchestrator must refuse to point Anthropic's connector at an untokened public endpoint rather than let a working preview mask missing auth. `Chat` returns a sentinel `llm.ErrChatDisabled` (before any streaming) when unconfigured. This avoids Go's typed-nil-interface trap outright — a conditionally-wired `*llm.ChatClient` stored in the `chatStreamer` interface would defeat a `== nil` guard and panic on the exact path meant to be safe — and keeps `cmd/orchestrator/main.go` wiring unconditional.
   - Test seam — one route, not a blend: `chat_test.go` (in-package) points the **real SDK client** at an `httptest.Server` speaking canned Anthropic SSE bytes (raw `message_start`/`content_block_start`/`content_block_delta`/`message_delta` (carrying a terminal `stop_reason` — without this frame the stop-reason-gated `done` never fires)/`message_stop` event frames — authored as wire bytes, not via `client_test.go`'s whole-`*Message` round-trip helper), constructing the `ChatClient` struct directly with `option.WithBaseURL(ts.URL)`/`option.WithAPIKey(...)`. This is what lets the tests assert the real wire artifacts (the `anthropic-beta` header, `mcp_servers`/`tools`/`max_tokens` request JSON) — an interface fake for the beta service produces no HTTP request and cannot see them. The `messagesClient`-style injection pattern (`client.go:40`) is *not* replicated here; the fake-injection seam for handler tests is the orchestrator's `chatStreamer` interface instead (Step 4).
4. **Orchestrator chat endpoint** (`internal/orchestrator/chat.go` + `chat_test.go`, `server.go`, `cmd/orchestrator/main.go`)
   - New narrow consumer interface in `server.go` beside the others: `chatStreamer interface { Chat(ctx, system string, msgs []llm.ChatMessage, emit func(llm.ChatEvent) error) error }`; new `Server` field + `NewServer` parameter; register `mux.HandleFunc("POST /goals/{id}/chat", s.handleChat)` in `Routes()` (`server.go:143`).
   - `handleChat`: stateless per request — the browser holds the transcript and posts `{"messages": [{"role": "user"|"assistant", "content": "..."}]}` each turn (matches the shell: "per browser message calls the Messages API"; no server-side session store). Validate non-empty messages and roles — every `role` must be `user` or `assistant`, `400` otherwise (`400` also on empty/undecodable body); the SDK has no assistant-message constructor (only `NewBetaUserMessage`), so Step 3 builds `BetaMessageParam{Role, Content}` directly and an unvalidated role would otherwise ride through to an API rejection masked as `502`. Resolve the goal via `lookupGoal` (`404` on unknown id — this *is* the session/context-level dataset/goal binding for the single-dataset MVP).
   - If the chat client is unconfigured (`MCP_PUBLIC_URL`, `ANTHROPIC_API_KEY`, or `MCP_AUTHORIZATION_TOKEN` empty), `Chat` returns `llm.ErrChatDisabled` before any streaming (Step 3); `handleChat` maps `errors.Is(err, llm.ErrChatDisabled)` → `503` with a vetted "agent preview is not configured" message rather than dialing Claude with a broken connector target. The disabled predicate lives in one place (`NewChatClient`), so the guard and the wiring cannot disagree.
   - Compose the system prompt from the bound goal: goal text, objective/Evaluation-Matrix summary, and instructions that the agent answers from the two read-only MCP tools (`store.Goal` fields via the existing `goalStore.Get`). Goals come in two shapes (`submit.go:118` vs `:159`): tabular goals carry `EvaluationMatrix`; document goals carry `TargetFields` and no matrix — when the matrix is empty, summarize `TargetFields` instead so a document goal's preview doesn't degrade to goal-text-only.
   - Stream the response with the exact `stream.go` conventions: same headers, `http.Flusher` assertion, and `data: <json>\n\n` frames discriminated by a top-level `type` field (`chat_text`, `chat_tool_use`, `chat_tool_result`, `chat_done`, `chat_error`) so Shell 10 reuses its frame-parsing approach. Reuse/mirror `writeEvent` (`stream.go:47`). **Ordering constraint:** do not call `WriteHeader`/flush before the first frame — the `200` status must commit lazily on the first frame write (as `stream.go` does via its first `Fprintf`), because the `502`/`503` JSON error paths below are only possible while the status is uncommitted; an eager up-front `WriteHeader(200)` + flush makes them unreachable.
   - Error handling per `submit.go:84` convention: a pre-stream Claude fault → `502` JSON error; a mid-stream fault (headers already sent) → emit a final `chat_error` frame with a masked generic message (log the real error), then end the stream.
   - Wire in `cmd/orchestrator/main.go`: unconditionally pass `llm.NewChatClient(cfg.Anthropic.APIKey, cfg.Anthropic.ChatModel, cfg.MCP.PublicURL, cfg.MCP.AuthorizationToken)` into `NewServer` — never a nil or conditionally-assigned value; the client itself reports disabled via `ErrChatDisabled` (Step 3).
   - **Existing `NewServer` call sites:** adding the `chatStreamer` parameter breaks compilation of four existing test constructions — the shared helper at `server_test.go:304` plus `server_test.go:546`, `server_test.go:569`, and `handlers_more_test.go:93`. Update all four in the same change, threading one shared fake `chatStreamer` (define it once beside the other `fake*` collaborators in `server_test.go`); otherwise the `go test ./internal/orchestrator` run Verification requires will not build.

## Verification

- `go build ./... && go vet ./...` — everything compiles with the new config fields, middleware, chat client, and handler.
- `go test ./internal/service ./internal/llm ./internal/orchestrator ./internal/config` — targeted packages:
  - `internal/service/auth_test.go`: table test — missing header / wrong scheme / wrong token → `401`; correct `Bearer <token>` → next handler runs; empty configured token → passthrough (auth disabled).
  - `internal/llm/chat_test.go`: real SDK client pointed at an httptest server speaking the Anthropic SSE wire format (raw `message_start`/`content_block_start`/`content_block_delta`/`message_delta` (terminal `stop_reason` — required for the `done` gate to fire)/`message_stop` event bytes; `ChatClient` built in-package with `option.WithBaseURL` per Step 3's test-seam route). Assert the outgoing request carries the `anthropic-beta: mcp-client-2025-11-20` header, a non-zero `max_tokens`, `mcp_servers[0]` with URL/token/`allowed_tools` exactly `["get_optimized_heuristics","trace_causal_chain"]`, and the `mcp_toolset` tools entry; assert emitted `ChatEvent` sequence (text deltas in order, exactly one terminal event, `done` last), a `refusal` stop reason yielding `error` and an unknown stop reason yielding `done` (the default arm), that an unconfigured client returns `ErrChatDisabled` without hitting the server, and that a mid-stream decode error surfaces as an `error` return, not a panic.
  - `internal/orchestrator/chat_test.go`: fake `chatStreamer` + `httptest.NewRecorder` — asserts `text/event-stream` headers; frames are `data: <json>\n\n` with correct `type` discriminators and no `event:` lines; `404` on unknown goal; `400` on empty messages; `503` when the fake returns `llm.ErrChatDisabled`; `502` on other pre-stream faults; mid-stream fault yields a terminal `chat_error` frame after partial `chat_text` frames. Assert the system prompt passed to the fake contains the goal's text (session binding).
- Manual smoke (no tunnel, no API key): `make up`, then `curl -i http://localhost:8082/ -H 'Authorization: Bearer wrong'` → `401` once `MCP_AUTHORIZATION_TOKEN` is set in `.env` (and `200`-family/MCP handshake response without the env set); `curl -N -X POST localhost:8080/goals/<id>/chat -d '{"messages":[{"role":"user","content":"hi"}]}'` → `503` "not configured" when `MCP_PUBLIC_URL` unset — proves the guard rather than a confusing connector failure.
- Live smoke (optional; needs `ANTHROPIC_API_KEY`, `MCP_AUTHORIZATION_TOKEN`, and a tunnel): `cloudflared tunnel --url http://localhost:8082`, set `MCP_PUBLIC_URL` to the tunnel URL, restart orchestrator, POST a chat message for a goal with published Meta-Heuristics → observe streamed `chat_text` frames and, for a question about the dataset, `chat_tool_use`/`chat_tool_result` frames naming `get_optimized_heuristics`. Note: the bundled 20-row `orders.csv` produces no Phase-2 winners at default MinSupport, so use a goal with real accumulated heuristics or expect tool calls that return empty matches (still a valid connector round trip).
- Edge cases to spot-check: goal id present but chat body `Content-Length: 0`; browser disconnect mid-stream (handler must return promptly — context cancellation propagates through `NewStreaming`); MCP server restarting mid-conversation (Claude surfaces a tool error — stream must end with `chat_error`, not hang); a `message_delta` carrying `stop_reason: pause_turn` (must not surface as a bare `chat_done` — see Step 3's stop-reason handling); a document goal (empty `EvaluationMatrix`) whose system prompt must summarize `TargetFields` instead.
